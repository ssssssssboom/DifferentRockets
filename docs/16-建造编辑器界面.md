# 16 · 建造编辑器界面（Editor / Menu / Ui）

> 本文覆盖 `core/src/com/differentrockets/ui/` 下三个文件：`EditorScreen.java`（1209 行，火箭建造编辑器）、`MenuScreen.java`（87 行，主菜单）、`Ui.java`（105 行，程序化 scene2d skin）。编辑器界面引用的大量 game 层概念（`ShipDesign` / `PartType` / `Attach` / `PartList`）此处只解释交互语义，数据结构的细节见对应文档。

## 1. EditorScreen 总览

`EditorScreen` 是"拖拽建造火箭"的全部界面逻辑，职责包括（类注释，EditorScreen.java:39-42）：零件调色板（palette）、带连接点吸附的拖放装配、90 度旋转、删除、分级（stage）列表、飞船保存/加载、发射入口。

### 1.1 屏幕布局（buildChrome）

整体是一个填满屏幕的 Scene2D `Table` 根，自上而下三行（EditorScreen.java:237-335）：

| 区域 | 内容 | 代码位置 |
|---|---|---|
| 顶栏第 1 行 | `Menu` 返回按钮 / 船名 `TextField` / `LAUNCH >>` 按钮 | EditorScreen.java:243-261 |
| 顶栏第 2 行 | `Rotate (R)` / `Save` / `Load` / `Stages` 四个等宽按钮 | EditorScreen.java:263-290 |
| 中部 | 左侧零件列表列（宽约 40% 屏宽）+ 右侧画布区 `canvasArea`（底部含激活组条 `groupBar`） | EditorScreen.java:292-320 |
| 底部 | 单行状态提示 `statusLabel`（所有操作反馈都写在这里） | EditorScreen.java:322-333 |

两个关键布局事实：

- 左侧调色板列宽固定为 `Gdx.graphics.getWidth() * 0.4f`（EditorScreen.java:319），释放拖出零件时也是用"屏幕 x 是否超过 40% 屏宽"判断落在画布还是列表上（EditorScreen.java:989-990）。
- 相机视口高固定 40 米（`cam.viewportHeight = 40`），初始位置偏移 `(-4.5, -3)`——注释说明这是因为竖屏 + 左侧调色板遮挡，画布可见带的中心并不等于屏幕中心（EditorScreen.java:131-137）。
- `canvasArea` 是一个透明 `Table`，它是 stage 中**唯一被 `EditorInput` 视为画布的区域**（字段注释，EditorScreen.java:52）。触摸事件分发靠 `stage.hit()` 判断：命中任何其他 actor（顶栏、调色板、激活组条、弹层）都视为"UI 拿走了这次点按"（EditorScreen.java:708-712）。

### 1.2 新建飞船的默认内容

构造函数里，如果传入的 `ShipDesign` 为空，会自动放一个指令舱 `pod-1` 并跑一次 `autoStage()`（EditorScreen.java:81-89）——即"每枚新火箭都从一个指令舱开始"。

## 2. 交互模型：三种放置零件的方式

代码里同时支持三种把零件放到画布上的路径，统一入口是 `selectPart()`（EditorScreen.java:922-926，武装 `placing` 幽灵零件并重置旋转）：

1. **拖出（drag-out，主要手势）**：按住左侧零件列表的一行，**向右**横向拖出列表、拖到画布上松手放置。这是第 3 节的主题。
2. **点选后点击放置（fallback）**：轻点列表行 → 武装 ghost → 在画布上点击放置（EditorScreen.java:734-743）。按住 Shift 点击可连续放置同类零件（`if (!Gdx.input.isKeyPressed(Input.Keys.SHIFT_LEFT)) placing = null;`，EditorScreen.java:741）。
3. 桌面端辅助：右键取消武装的 ghost、右键点已放置零件直接删除（EditorScreen.java:721-733）；`R` 键旋转、`ESC` 依次关闭弹层 → 取消 ghost → 返回主菜单（EditorScreen.java:907-914）。

放置后的统一收尾：清空选择集、重建激活组条、`design.autoStage()` 重新自动分级、重建分级列表（EditorScreen.java:736-740）。

## 3. 拖出手势状态机（DragOutInterceptor）

### 3.1 为什么需要一个原始拦截器

调色板列表放在一个 `ScrollPane` 里。代码注释记录了核心难点（EditorScreen.java:143-150）：**ScrollPane 会在拖动中途偷走/取消 Scene2D 的 touch focus**，而这个 gdx 版本里 focus 路由的事件不触发 capture listener，所以无论行内 listener 还是 stage 级 listener 都无法可靠完成"横向拖出"手势。因此拖出识别被放在 `InputMultiplexer` 中 **stage 之前**的一个原始 `InputAdapter`（`DragOutInterceptor`）里：

```java
mux.addProcessor(dragOutInterceptor); // 最前：识别横向拖出
mux.addProcessor(stage);              // Scene2D UI
mux.addProcessor(editorInput);        // 画布手势（拖动/缩放/点选）
```

（EditorScreen.java:143-154）

拦截器只在"横向拖出已经真正开始"之后才消费事件；普通的点按和竖直滚动原样流给 stage。

### 3.2 状态机

字段（EditorScreen.java:55-57, 171-175）：

- `candidate`：touchDown 时命中的调色板行对应的 `PartType`（候选，尚未确认为拖出）。
- `dragOutType`：非 null 表示拖出手势已激活。
- `dragScrX/dragScrY`：拖出手指的最新屏幕坐标。

状态迁移：

| 事件 | 条件 | 动作 |
|---|---|---|
| `touchDown` | pointer 0 且未在拖出中 | 记录 `candidate = paletteRowAt(x,y)` 和按下点；**返回 false 不消费**（EditorScreen.java:177-182） |
| `touchDragged` | 未激活，`|dx| > 14` 且 `\|dx\| > \|dy\|` | 判定为横向拖出 → `beginDragOut()`，返回 true 开始消费（EditorScreen.java:190-198） |
| `touchDragged` | 已激活 | 更新手指坐标，返回 true（ScrollPane/stage 不许再看到这次拖动） |
| `touchUp` | 已激活 | `finishDragOut()` 并消费释放事件（EditorScreen.java:202-207） |
| `touchCancelled` | 已激活 | 清空 `dragOutType` 与 `placing`（EditorScreen.java:209-217） |

`paletteRowAt()` 用每个 `PaletteItem` 的 stage 坐标包围盒做命中测试（EditorScreen.java:221-233），不依赖 Scene2D 的事件路由。

### 3.3 beginDragOut / finishDragOut

- `beginDragOut()`（EditorScreen.java:940-953）：先 **`stage.cancelTouchFocus()`**，然后武装 ghost（`placing = t`）、重置旋转、记录 `dragOutType`。
- `finishDragOut()`（EditorScreen.java:983-1003）：防御性地再次 `cancelTouchFocus()`；若松手点 x > 40% 屏宽（画布侧），将坐标 unproject 到世界、`snap()` 吸附后放入 `design.parts`；否则视为拖回列表取消。最后清掉 `placing`。

### 3.4 历史 bug：按压未释放（focus 泄漏级联）

`DragOutInterceptor` 的类注释（EditorScreen.java:159-170）和 `beginDragOut` 的注释（EditorScreen.java:941-946）完整记录了一个第 8 轮修复的严重 bug，称为 **"input dead after drag-out"**：

1. 调色板行在 touchDown 时拿到了 Scene2D touch focus；
2. 拦截器接管手势后会吞掉释放时的 touchUp，stage 里的行永远收不到配对的 touchUp——**按压未释放，focus 泄漏**；
3. 下一次手势时，这个陈旧 focus 会向行触发一次**幻影 touchUp**（误武装一个 ghost 放置）；
4. 同时 stage 又吞掉那次 touchUp，`EditorInput` 自己的 `touchPtrA` 永远等不到释放——泄漏的 `touchPtrA` 让之后所有单指手势都被当成双指操作，输入彻底"死亡"。

修复就是 `beginDragOut()` 里第一时间 `stage.cancelTouchFocus()`（EditorScreen.java:946）。`finishDragOut()` 里的第二次调用（EditorScreen.java:987）是防御拖出中途第二根手指在调色板上又武装了一个 focus。

同类防护还有：

- `EditorInput.touchDown` 开头检查 `dragOutType != null` 直接放行——拖出占用 pointer 0 时，第二根手指不允许在画布上放 ghost 或开始平移（EditorScreen.java:690-692）。
- `hide()` 离开屏幕时清空**所有**瞬态指针状态（拖出、candidate、双指、平移/拖动索引），防止泄漏进下一次 `show()`（EditorScreen.java:1191-1208）。
- `EditorInput.touchCancelled` 被系统打断时同样清空全部瞬态状态（EditorScreen.java:895-904）。

## 4. 触摸事件分发（EditorInput）

`EditorInput`（EditorScreen.java:687-920）处理 stage 之外的画布手势。它维护一套**自己的指针状态机**，不信任 `Gdx.input.getX(pointer)`：

- `touchPtrA` / `touchPtrB`：第一/第二根手指的 pointer id（-1 表示无）；
- `gpaX/gpaY/gpbX/gpbY`：两根手指的最新坐标日志，每个事件都更新。

注释解释了原因（EditorScreen.java:695-700）：后端对 synthetic 事件和已遗忘 pointer 的 `getX(pointer)` 查询不可靠（与"dead-pointer pinch crash"同类），所以双指手势中另一只手指的位置永远取自己的事件日志。

### 4.1 优先级

`touchDown` 的判断顺序（EditorScreen.java:689-716）：

1. 拖出手势进行中 → 直接放行（见 3.4）。
2. `touchPtrA != -1` → 这是第二根手指：升级为双指相机手势，**取消但不完成**当前单指操作（`panning=false; downIndex=-1; dragIndex=-1; dragMoved=false`）。第三根手指忽略。
3. `stage.hit()` 命中非 `canvasArea` 的 actor（顶栏/调色板/激活组条/弹层）→ 放行给 stage。
4. 否则进入 `firstFingerDown()`（单指画布操作），处理成功才登记 `touchPtrA`。

### 4.2 单指画布操作（firstFingerDown）

按序判断（EditorScreen.java:719-759）：

1. **右键**：取消 ghost；若点在零件上则删除该零件并重新自动分级。
2. **`placing != null`**：在吸附后的位置放置 ghost 零件。
3. **点在已放置零件上**（`partAt()` 命中）：记录 `downIndex`——此时**不区分**点选还是拖动，等后续事件决定（tap=切换选中，移动=拖走）。
4. **空白处**：进入 `panning` 平移视野。

`partAt()` 的拾取容差为 `max(2 m, 48 px 换算的世界单位)`（EditorScreen.java:559-561），在零件局部坐标系（含旋转）做包围盒测试，重叠时取中心最近者。

### 4.3 拖动中的晋升逻辑（touchDragged）

- 双指已建立 → `pinchDrag()`（见 4.4）。
- 单指：若 `downIndex >= 0` 且位移超过 12 px → **晋升为拖动移动**：`dragMoved=true; dragIndex=downIndex`，之后的移动实时把零件吸附（`snap()`）到新位置（EditorScreen.java:806-823）。
- 否则若 `panning` → 按 `viewportHeight/屏高` 比例平移相机（EditorScreen.java:824-831）。

### 4.4 双指相机手势（pinchDrag）

`pinchDrag()`（EditorScreen.java:762-791）：两指**中点的位移**做平移（用 unproject 求精确世界增量），**两指距离比**做缩放，缩放锚定在中点（先 unproject 记录中点世界坐标，改视口后再 unproject 一次并把相机补回去）。视口高 clamp 在 `[5, 200]` 米。桌面端滚轮缩放走 `scrolled()`，每档 ×1.1 / ×0.9（EditorScreen.java:887-892）。

### 4.5 释放逻辑（touchUp）

- 释放的是 `touchPtrB`：双指手势结束，剩余手指从自己的坐标日志**重新锚定**为平移起点（EditorScreen.java:837-845）。
- 释放的是 `touchPtrA` 且 B 还在：B 晋升为 A（EditorScreen.java:847-856）。
- `downIndex >= 0` 且未移动 → 这是**点选**：在 `selected` 集合里 toggle 该零件（用于激活组编制），并刷新激活组条（EditorScreen.java:858-864）。
- `downIndex >= 0` 且移动过 → 拖动结束，重新自动分级（EditorScreen.java:865-868）。
- `panning` 且位移 < 12 px → 视为"点了空白"：清空选择集（EditorScreen.java:874-881）。

## 5. 零件列表（左侧调色板）

- 数据来自 `PartList.palette()`，每个零件一行 `PaletteItem`（EditorScreen.java:298-304）。
- 列表包在 `ScrollPane` 里，**只允许竖直滚动**（`setScrollingDisabled(true, false)`，EditorScreen.java:305-307）。
- `PaletteItem` 行内显示零件名（2 倍字号、自动换行）和"类型 + 质量（吨）"（1.5 倍字号），背景为深灰 tint（EditorScreen.java:1010-1022）。行不设固定高度，**整行都是触摸目标**（EditorScreen.java:300-303 注释）。
- 行内 listener 处理"轻点武装 ghost"的 fallback 路径：位移 < 14 px 且**调色板没有滚动过**且事件未被取消，才算一次 tap（EditorScreen.java:1028-1052）。注释记录了为什么额外比较 `paletteScroll.getScrollY()`：ScrollPane 偷走竖直拖动后不会给行路由 touchDragged/cancel，实测一次 180 px 滚动后 `moved=false` 且未取消——只看自身位移会把滚动误判为点按。

## 6. 旋转与连接吸附

### 6.1 旋转

`rotateGhost()`（EditorScreen.java:650-682）按 90° 步进（`rot ∈ 0..3`，渲染时乘 90°），优先级：

1. 正在放置的 ghost（若该 `PartType` 未设 `disableEditorRotation`）；
2. 正在拖动的已放置零件；
3. **点选选中的零件集合**——注释记录这是第 9 轮修的 bug：旧代码只认识 ghost 和拖动中的零件，tap 选中的零件按 Rotate 没反应（EditorScreen.java:665-667）。现在会旋转所有选中零件。

### 6.2 连接吸附（snap）

`snap()`（EditorScreen.java:581-620）在放置/拖动时把 ghost 位置吸附到其他零件的连接点上：

- 吸附半径 2.2 m。
- 对 ghost 的每个 `AttachPoint` 和每个已放置零件的每个 `AttachPoint`，取各自的**世界坐标线段**（`attachWorldSeg()`，EditorScreen.java:623-631），用 `Attach.closestBetweenSegments()` 求线段间最近点对；最近的一对胜出，把 ghost 平移 `co - cm` 使两点重合。
- **边缘吸附（edge-aware）**：edge 型连接点允许沿其整条边线段的任意位置接触，ghost 沿配合边滑动；且当胜出的接触对涉及 edge 型连接点时，滑动位置量化锁到 0.25 m 网格（`Attach.quantizeAlongSegment()`）；center 型点对保持精确接触位置（EditorScreen.java:584-588, 604-614 注释）。

渲染上，`placing != null` 时 ghost 以 0.6 透明度画出，并用绿点标出 ghost 与已放置零件的全部连接点（大点 0.25 m = ghost 的，小点 0.18 m = 已有的）（EditorScreen.java:1084-1104）。

## 7. 激活组编制 UI（activation groups）

- 模型：每个零件一个 `group` 字段（0 = 未分组，1..8 = 组号，**一个零件只属于一个组**）。
- 多选：点选零件在 `selected` 集合里 toggle（见 4.5）；选中零件画青色描边矩形，带组号的零件在右上角画蓝色圆点 + 组号数字（字号随缩放保持恒定屏幕大小，EditorScreen.java:1107-1146）。
- `groupBar` 位于画布区底部，**只在选择集非空时出现**（`rebuildGroupBar()`，EditorScreen.java:337-385）。因为画布列很窄，排成三行：`Grp: 1-4` / `5-8` / `Clear grp` + `DEL parts`。
- `toggleGroup(grp)`（EditorScreen.java:387-397）：若所有选中零件都已在该组 → 全部移出（group=0）；否则全部设入该组。
- `Clear grp`：清空所有选中零件的组。`DEL parts`：触屏友好的删除（手机上没有右键），按索引倒序删除选中零件后重新自动分级（EditorScreen.java:368-381）。

### 7.1 分级（Stages）与保存/加载/发射

- 分级列表 `stageTable` 竖屏下放不下，收在 `Stages` 按钮弹出的模态对话框里（EditorScreen.java:417-433）。分级内容本身由 `design.autoStage()` 自动计算，编辑器只展示零件名列表。
- 模态弹层统一由 `newOverlay()` 创建：全屏半透明黑底，自带一个消费所有 touchDown 的 listener，防止点按泄漏到下层画布（EditorScreen.java:435-446）。`closeOverlay()` 移除。
- Save/Load：JSON 存到 `Gdx.files.local("save/ships")`，文件名由船名过滤非法字符得到（EditorScreen.java:485-534）。
- `LAUNCH >>` 弹出发射行星选择器：遍历 `game.world.sun.flatten()` 打平的行星列表，只列 `launchEnabled` 的行星，按钮上标注表面重力；选中后 `launch()` 先 `autoStage()` 再 `world.launchShip()` 并切到 `SandboxScreen`（EditorScreen.java:457-483, 542-546）。

## 8. Ui 类：程序化 scene2d skin

`Ui`（Ui.java:16-105）不依赖任何 GUI 图集美术资源，用一张 8×8 白色 `Pixmap` 生成的 `Texture` 加 `tinted(Color)`（`TextureRegionDrawable.tint`，Ui.java:96-98）为所有控件生成纯色背景。提供的样式：`Label`、`TextButton`、`TextField`、`Slider`、`ScrollPane`、`List`、`SelectBox`、`Window`，统一深蓝灰配色。

### 8.1 按钮"抬起回灰"约定

`TextButton` 样式（Ui.java:35-46）：

- `up` = 灰蓝 `(0.22, 0.25, 0.33)`，`down` 和 `over` 更亮，提供按压反馈；
- **`checked` 被刻意设为与 `up` 完全相同**。注释记录了原因（round 14，Ui.java:40-43）：scene2d 的 `Button` 会在**每次点击**都翻转 `checked` 状态，导致手指抬起后绿色 checked tint 一直残留。把 checked 面设成与 up 一致后，按钮抬起永远回到灰色，瞬时反馈只来自 `down`/`over`。

**约定**：本项目里所有按钮都是"瞬时按钮"，禁止依赖 scene2d 的 checked 状态做开关语义；需要开关态的 UI（如激活组按钮）靠外部数据 + 重绘表达，不靠按钮自身状态。

### 8.2 通用工具

- `tinted(Color)`：各 Screen 用它给面板/弹层做半透明深色背景（如编辑器顶栏 `(0.09, 0.1, 0.15, 0.95)`）。
- `dispose()` 释放 skin 和白色纹理（Ui.java:100-104）。

## 9. MenuScreen：入口流程

`MenuScreen`（MenuScreen.java:16-87）是游戏启动后的主菜单：深蓝背景 + 标题 `DifferentRockets` / 副标题 `A SimpleRockets-style 2D space sandbox` + 三个大按钮（宽 400 高 88）：

| 按钮 | 行为 | 代码位置 |
|---|---|---|
| `Build New Rocket` | `game.setScreen(new EditorScreen(game, null))` —— 新建设计进编辑器 | MenuScreen.java:42-46 |
| `Continue Sandbox` | `game.world.load()` 读档后直接进入 `SandboxScreen` | MenuScreen.java:47-52 |
| `Reset World` | `world.clearSave()`、销毁所有现存 `Ship`、清空 `world.ships`、`active=null`、世界时间归零；**不切换屏幕**，停留在菜单 | MenuScreen.java:53-61 |

输入处理极简单：`Gdx.input.setInputProcessor(stage)`，没有编辑器那样的多级分发（MenuScreen.java:27-28）。`render()` 只清屏并驱动 stage（MenuScreen.java:71-76）。

编辑器内返回主菜单的入口有两处：顶栏 `Menu` 按钮（EditorScreen.java:251-256）和 `ESC` 键的最终分支（EditorScreen.java:909-913）。

## 10. 改动编辑器时的注意事项（来自代码注释的教训汇总）

1. **任何接管手势的代码都必须负责配对的 touchUp 或调用 `stage.cancelTouchFocus()`**，否则复现"input dead after drag-out"级联（见 3.4）。
2. 不要改用 `Gdx.input.getX(pointer)` 获取另一只手指的位置——维护事件日志（`gpaX/gpaY/gpbX/gpbY`）是有意为之（EditorScreen.java:695-700）。
3. `EditorInput.touchDown` 的画布/UI 判定依赖 `canvasArea` 是 stage 里唯一的"透明画布"actor；新增全屏 UI 面板时注意它会被 `stage.hit()` 命中，从而天然拦截画布手势——弹层也应像 `newOverlay()` 一样主动消费事件。
4. 调色板行的 tap 判定必须同时检查 ScrollPane 滚动量（见第 5 节），去掉 `paneScrolled` 检查会把列表滚动误判为点按。
5. 编辑器留了若干 smoke-test 钩子（`getPlacing()` / `isSelected()` / `snapForTest()` / `hitInfo()` / `emptyCanvasPointForTest()` 等，EditorScreen.java:93-127, 633-637, 958-976），自动化测试依赖它们，重构时不要删除。
