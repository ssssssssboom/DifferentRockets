# 13 · 地形系统（TerrainSystem / TerrainScript）

> 适用范围：`game/core/src/com/differentrockets/game/TerrainSystem.java`（600 行）与 `TerrainScript.java`（204 行），配套脚本 `game/core/assets/mods/terrain.lua`（玩家可改，与 `/sdcard/DifferentRocket/mod/terrain.lua` 同步）。
>
> 当前实现是「round 18 柱状地形重写」（TerrainSystem.java:31-68 的类注释自述）。读懂本文后，你应当能解释：为什么地表在视觉上和物理上永远是同一个形状、为什么飞船落在地面上不会被行星"吞掉"、以及改一行 lua 为什么立刻全局生效。

## 1. 总体模型：柱状四边形列环

### 1.1 列（column）与交点（junction）

整个行星地表被建成一个**列环（ring of columns）**（TerrainSystem.java:32-40）：

- 每列宽 `blockWidthM` 米弧长，默认 **4 m**（`DEF_BLOCK_W`，TerrainSystem.java:72）。
- 地表的绝对高度只在**交点（junction）**上定义：交点 `j` 的高度 `h[j]` 是从行星中心算起的**绝对半径（米）**。
- **第 i 列 = 交点 `h[i]` 与 `h[i+1]` 之间的四边形**：
  - 顶边（地表皮肤）：`(x_i, h_i) → (x_{i+1}, h_{i+1})`
  - 底边：同一条边向下 `depthM` 米（默认 **32 m**，`DEF_DEPTH`，TerrainSystem.java:73）

因为相邻两列**共享同一个交点高度**（高度只在交点上采样一次），列与列之间在构造上就是无缝的——不存在"两块各自采样导致接缝错开"的问题。

### 1.2 列数与列宽的自我调整

进入一颗行星的管理范围时，`setupPlanet()` 计算（TerrainSystem.java:261-266）：

```java
double circ = 2 * Math.PI * planet.radius;
totalCols = Math.max(8, (int) Math.round(circ / blockW));
colW = circ / totalCols; // adjusted so columns tile the planet seamlessly
```

即：先按 `blockW` 四舍五入出整数列数 `totalCols`，再反推实际列宽 `colW`，保证整圈**精确闭合**。chunk 粒度固定为 64 列（`COLS_PER_CHUNK`，TerrainSystem.java:84，4 m 列宽即 256 m/chunk）。

### 1.3 一套顶点数据同时喂渲染和物理

类注释明确写道："the SAME vertex data builds both the render mesh and the collision fixtures (what you see is what you collide with)"（TerrainSystem.java:38-40）。渲染 mesh（`loadChunk`，TerrainSystem.java:384）和碰撞 fixture（`createBody`，TerrainSystem.java:496）都从 `junctionHeight()` 取同一份交点高度——这是"看到的地面就是撞到的地面"的根本保证。

## 2. lua `surfaceHeight` 与交点高度缓存

### 2.1 lua 侧的接口

`TerrainScript` 是 Java 与 `mod/terrain.lua` 之间的桥（TerrainScript.java:12-23）。terrain.lua 提供两个函数和一个配置表：

| lua 成员 | 签名 | 语义 |
|---|---|---|
| `surfaceHeight(info, xArcMeters)` | → 绝对半径（米） | **柱状地形的主入口**（round 18 新增），驱动渲染 mesh 和碰撞四边形（TerrainScript.java:114-121） |
| `terrainHeight(planetName, angleRad)` | → 相对高度（米） | 旧版接口，仅作 fallback（TerrainScript.java:96-112） |
| `terrainRender = {...}` | 表 | 全部可调参数：`blockWidthM / depthM / rangeM / physicsRangeM / friction / restitution / topBrightness / bottomBrightness / bandVariation / texture / deepColor`（terrain.lua:32-44） |

`ensureBound()`（TerrainScript.java:40-94）在脚本（重）加载后向 lua 注入：

- `planetInfo` 表：每颗行星的 `name / radius / minHeight / maxHeight / noise / ranges`（`ranges` 是分段高度区间，TerrainScript.java:55-65）；
- `noise` 表：`value1`（1D 无缝 value noise，lattice 按整数周期回绕，TerrainScript.java:181-189）、`value2`（2D value noise，TerrainScript.java:192-203）、`hash(string)`（Java 兼容的字符串 hash，用作行星种子）。

这些噪声函数是**确定性纯函数**，镜像了 `Planet` 内置生成器（`Planet.builtinHeightAt`，Planet.java:142）。

### 2.2 交点高度缓存 `hCache`

`junctionHeight()`（TerrainSystem.java:363-375）是所有地形高度的唯一 Java 入口：

```java
private double junctionHeight(int j) {
    int c = ((j % totalCols) + totalCols) % totalCols;   // 交点索引回绕
    Double v = hCache.get(c);
    if (v != null) return v;
    double x = c * colW;
    double r = TerrainScript.surfaceHeight(planet.name, x);
    if (Double.isNaN(r) || Double.isInfinite(r) || r < planet.radius * 0.5) {
        r = planet.radius + planet.heightAt(x / planet.radius); // built-in fallback
    }
    ...
}
```

要点：

1. **按交点索引缓存**（`hCache: Map<Integer, Double>`，TerrainSystem.java:96）。因为 lua 函数是确定性纯函数，每个交点只需调 lua 一次；之后渲染、物理、水面多边形全部命中缓存。类注释（TerrainSystem.java:51-52）："junction heights are CACHED per junction index ... so Lua is called once per NEW junction only"。
2. **健壮性护栏**：lua 返回 NaN / Infinity / 低于 `0.5 * radius` 的非法值时，回退到内置生成器（TerrainSystem.java:369-371）。
3. **容量安全阀**：`HEIGHT_CACHE_CAP = 200000`（TerrainSystem.java:87），超限整体清空重填——因为是确定性纯函数，清缓存不丢正确性，只丢一点性能。

## 3. 10 Hz 加载窗口管理

### 3.1 双层窗口：渲染 ±100 km，物理 ±10 km

默认值（TerrainSystem.java:74-75，可被 `terrainRender.rangeM / physicsRangeM` 覆盖）：

| 窗口 | 默认 | 作用 |
|---|---|---|
| `rangeM` | ±100 000 m | chunk（mesh + 数据）的加载/渲染窗口 |
| `physicsRangeM` | ±10 000 m | 只有此窗口内的 chunk 才有 Box2D body/fixture |

**为什么物理窗口要小一个数量级？** 类注释给出了精确的成本账（TerrainSystem.java:53-56）：100 km 渲染范围在 4 m 列宽下是 **~25 000 列**，若每列一个 fixture 就是 ~25 000 个 fixture；而玩家实际能接触到的地面只有附近几公里。渲染 mesh 覆盖全窗口（远处地面要看得见），碰撞体只覆盖 ±10 km（远处地面摸不到）。"Chunks crossing the physics boundary gain/lose their body."（TerrainSystem.java:56）——chunk 跨越物理边界时动态获得/销毁 body。

### 3.2 管理节拍：10 Hz

窗口管理不在每帧跑，而是以 `REFRESH_S = 0.1` s（10 Hz）节流（TerrainSystem.java:86, 311-316）：

```java
refreshT += Gdx.graphics.getDeltaTime();
if (refreshT >= REFRESH_S) {
    refreshT = 0;
    manage(shipUniverse);
}
```

设计意图（TerrainSystem.java:49-50）：10 Hz 管理只需要在窗口**边缘**创建/移除 chunk，每帧做是浪费。

### 3.3 `manage()` 的三件事

`manage()`（TerrainSystem.java:320-353）每 0.1 s 执行：

1. **算窗口**：把飞船位置换算成行星系弧长坐标 `shipArc`，求出中心 chunk，向两侧各取 `span = ceil(rangeM / chunkArc) + 1` 个 chunk（TerrainSystem.java:327-329），构成 `want` 集合，缺啥 `loadChunk` 啥；
2. **物理成员资格**：遍历已加载 chunk，用**回绕弧距** `wrappedArcDist()`（TerrainSystem.java:356-360，处理跨 0°/360° 的最短弧距）判断是否进入 ±`physRangeM`——进入且无 body → `createBody()`；离开且有 body → `destroyBody()`（TerrainSystem.java:338-343）；
3. **卸载**：不在 `want` 里的 chunk 整体 dispose（mesh + body 一起释放，TerrainSystem.java:345-352）。

另外，活动行星的选择在 `update()` 开头（TerrainSystem.java:269-288）：每帧取"离表面最近"的行星，**离表面超过 200 km 则完全不管理地形**；换行星时清 chunk、清高度缓存、重新 `setupPlanet()`。

## 4. 碰撞体生成与防回归措施

`createBody()`（TerrainSystem.java:496-544）为一个 chunk 建碰撞体：**每列一个四边形 fixture**，与渲染 mesh 用同一份交点高度。类注释（TerrainSystem.java:58-67）明确列出从旧分块系统继承的四条防回归措施，逐条对应代码如下。

### 4.1 KINEMATIC body + 速度驱动（防"瞬移地面吞飞船"）

每个 chunk 的 body 类型是 `BodyDef.BodyType.KinematicBody`（TerrainSystem.java:502），注释写明 "velocity-driven ground"。

关键在于它**不是每帧 setTransform 瞬移**，而是在 `update()` 里按目标位移/帧时长换算成线速度（TerrainSystem.java:296-309）：

```java
double tx = px + c.cx, ty = py + c.cy;
if (c.hasLast && simDt > 1e-9) {
    c.body.setLinearVelocity(
            (float) ((tx - c.lastBX) / simDt),
            (float) ((ty - c.lastBY) / simDt));
} else {
    c.body.setTransform((float) tx, (float) ty, 0);  // 首帧才瞬移
    c.body.setLinearVelocity(0, 0);
}
```

**为什么必须这样**：行星会动（rails 轨道 + floating origin 重定位），地面 body 的目标位置每帧都在变。如果用 static body + 瞬移，接触求解器看到的地面速度永远是 0，落地飞船会被"瞬移的静态碰撞体"吞进去。速度驱动让 contact solver 看到地面的**真实表面速度**，飞船靠摩擦被行星带着走（注释称其为 "the lone-pod sinking fix"，TerrainSystem.java:290-293）。首帧无历史位置时才允许瞬移一次。

### 4.2 chunk 局部坐标（防 Box2D float32 断言）

fixture 顶点全部减去 chunk 中心 `(c.cx, c.cy)`，转成 **chunk 局部坐标**（TerrainSystem.java:515-522）。原因（TerrainSystem.java:63-64）：以行星中心为原点的顶点坐标绝对值约 637 km，在 Box2D 2.3 的 float32 质心计算里会触发原生断言；chunk 局部坐标把数值压到 ±128 m 量级。

### 4.3 列间重叠 `SEAM_OVERLAP_M`（防隧道缝、防侧滑卡缝）

```java
private static final double SEAM_OVERLAP_M = 0.05;  // column overlap: no gaps/snags
```

（TerrainSystem.java:85）。建 fixture 时，每列的左右角度各向外扩 `ovAng = SEAM_OVERLAP_M / radius`（TerrainSystem.java:507-511），即相邻列的碰撞四边形互相**重叠 5 cm**。列顶边是直线段、行星表面是弧线，无重叠时列间会有微小缝隙，高速零件可能 tunneling 钻进缝里或在缝上侧滑卡滞；5 cm 重叠从几何上消除了缝隙。

### 4.4 restitution = 0 + 高摩擦 + 退化四边形护栏

- **restitution = 0**（`DEF_RESTITUTION`，TerrainSystem.java:77）：地面完全无弹性，落地不弹跳（TerrainSystem.java:66）。
- **friction 默认 1.0**（TerrainSystem.java:76）：高摩擦防落地后侧滑（terrain.lua:20 注释 "~1.0 stops post-spawn sideslip"）。两者都可被 lua 覆盖并经 clamp（TerrainSystem.java:226-227）。
- **退化四边形护栏**（TerrainSystem.java:523-534）：交给 Box2D 之前，先用 double 精度算四边形面积（2 倍有向面积），`|area2| < 0.01` 或 NaN 直接跳过该 fixture，并打日志（只记前 5 次，`degenerateSkips` 计数器，TerrainSystem.java:114）。注释（TerrainSystem.java:67）："degenerate-quad guard in double precision before Box2D sees a polygon"——Box2D 拿到退化/NaN 多边形会原生断言崩溃，必须提前拦。

## 5. 渲染

### 5.1 每列两个四边形：渐变外壳 + deep 填充

`loadChunk()`（TerrainSystem.java:394-446）为每列生成 **8 个顶点**（4 shell + 4 deep，TerrainSystem.java:397）：

| 部分 | 顶点 | 颜色 | 作用 |
|---|---|---|---|
| **shell quad** | 地表皮肤 → `h - depthM` | 顶边 `crustColor * topBrightness * jitter`，底边 `crustColor * bottomBrightness`（TerrainSystem.java:417-421） | 可见地壳，垂直亮度渐变 |
| **deep quad** | `h - depthM` → 焊底面 | 纯色 `deepColor`（默认暗棕 0.23/0.15/0.09） | 填充到基准面的实心块 |

- **顶点色渐变**：顶边亮度 `topB = 1.35`（clamp 到 1）、底边 `botB = 0.25`，中间由 GPU 插值出渐变（TerrainSystem.java:78-79, 418-421）。
- **逐列亮度抖动**：`colJitter(colIdx)`（TerrainSystem.java:378-382）用整数 hash 产生 [-1,1] 的确定性伪随机值，乘上 `bandVariation`（默认 ±0.06）调制顶边亮度——"texture-grain substitute"，让无贴图地面不显得塑料般平滑。

### 5.2 deep 填充焊到基准面（防悬空条带，round 19 修复）

deep quad 的底边不是 `h - crust`，而是（TerrainSystem.java:413-414）：

```java
double botL = Math.min(hL - crust, planet.radius);
```

`crust` 上限 `MAX_CRUST = 260 m`（TerrainSystem.java:83, 395）。代码里的注释（TerrainSystem.java:406-412）完整记录了这个 bug：高于基准面 260 m 以上的山脊，壳体在皮肤下 260 m 就结束了；而弧长超过 ~20 km 后，画在半径 R 处的行星本体圆盘会低于当地地平线——于是远处的 chunk 看起来像一条悬在星空背景上的**棕色直条**（"floating-mountains fix"）。把 deep 填充**焊到基准面半径 R**（"Filling to R welds every chunk onto the body disc"）后，每个 chunk 都与行星本体圆盘无缝接上。

### 5.3 可选贴图与单 shader 路径

`terrainRender.texture` 可以指定一张贴图名（如 `PlanetCrustSmearth.png`），每个四边形的 uv 把贴图拉伸铺满（TerrainSystem.java:423-427；资源经 `Res.asset()` 解析，玩家目录优先，TerrainSystem.java:244）。无贴图时绑定一张 1×1 白图 `whiteTex`（TerrainSystem.java:161-167），因为 shader 的片元永远执行 `texture2D(u_texture, v_texCoord) * v_color`（TerrainSystem.java:155-157）——**一个 shader 同时服务贴图/无贴图两条路径**（TerrainSystem.java:557-558）。贴图加载失败降级为渐变并记日志（TerrainSystem.java:249-252）。

渲染时所有 chunk 共用一个平移 model 矩阵（行星位置 - floating origin，TerrainSystem.java:553-555），mesh 顶点本身在行星系坐标里。

### 5.4 水面

若行星 `waterDensity > 0` 且 chunk 内有低于海平面（r = R）的交点，构建水面多边形 `waterPoly`（TerrainSystem.java:448-476）：上边缘走海平面弧、下边缘走被淹没的地形。渲染时用 ShapeRenderer 以半透明蓝 `(0.15, 0.35, 0.75, 0.75)` 从顶点 0 扇形三角化填充（TerrainSystem.java:569-589）。

## 6. 与 `Planet.heightAt` 的统一：历史双轨制 bug

这是 round 18 修掉的一个重要坑，涉及三处代码，务必理解：

**旧世界（双轨制）**：游戏里有**两条互不知情的地形高度路径**——

- 渲染/碰撞走 lua `surfaceHeight`（柱状地形，含 `specialTerrains` 手工地形区）；
- 游戏逻辑查询（高度表、出生台、rails 地板、水面判定）走 lua `terrainHeight` / 内置生成器，而 **`terrainHeight` 不知道 specialTerrains 的存在**（TerrainScript.java:139-146）。

后果：在 specialTerrains 区域（例如手工削平的沿海平原出生区），飞船可能停在"自然地形高度"的**隐形平面**上，悬浮在可见特殊地形之上或埋在其下（TerrainScript.java:144-146：a ship could sit on an invisible plane ... above/below the visible special terrain）。

**修复（单轨制）**：`Planet.heightAt()` 现在**优先**路由到 `surfaceHeight`（Planet.java:128-139）：

```java
public double heightAt(double angleRad) {
    double h = TerrainScript.heightAboveDatum(name, angleRad);  // 先走 surfaceHeight
    if (!Double.isNaN(h) && !Double.isInfinite(h)) return h;
    h = TerrainScript.heightAt(name, angleRad);                 // 兼容无 surfaceHeight 的旧玩家脚本
    if (!Double.isNaN(h)) return h;
    return builtinHeightAt(angleRad);                           // 内置生成器兜底
}
```

其中 `heightAboveDatum()`（TerrainScript.java:148-168）把角度换算成弧长（`angleRad * radius`）调 lua `surfaceHeight`，再减去半径得到相对高度。由此**所有游戏性高度查询都与柱状碰撞/渲染地形一致，specialTerrains 包含在内**（Planet.java:130-133 注释）。`Planet.heightAt` 的调用方包括 `GameWorld`（高度表、出生台、水面判定等，GameWorld.java:206,229,293,404,602,725,741,836）、`Ship`（Ship.java:604,631）与 `OrbitPredictor` 的落地回交接（OrbitPredictor.java:228）。

反向同理：`TerrainSystem.junctionHeight()` 在 lua 失效时回退到 `planet.heightAt()`（TerrainSystem.java:370）——两条路径互为 fallback，正常情况下收敛到同一个 `surfaceHeight`。

## 7. 热重载机制

地形的热重载分三层，全部基于**身份令牌（identity token）比较**，无需手动重启游戏：

### 7.1 底层：`LuaScript` 的 1 秒轮询

`LuaScript.refreshIfNeeded()`（LuaScript.java:74-126）对玩家 mod 文件 `/sdcard/DifferentRocket/mod/terrain.lua` 每秒 stat 一次，`lastModified` 变了就用 luaj `JsePlatform.standardGlobals()` 重新编译执行；玩家文件缺失则回退内置 assets。**每次重载产生一个新的 `Globals` 对象实例**——这就是重载检测的令牌。编译失败的脚本标记 broken（只记一次日志），调用方回退内置行为（LuaScript.java:11-17, 119-125）。

### 7.2 中层：`TerrainScript` 的重绑定

`TerrainScript.ensureBound(world)` 在 `refreshParams()` 开头每帧调用（TerrainSystem.java:180）。它比较当前 `Globals` 与上次注入时的 `bound`（TerrainScript.java:43-44）：不同（= 脚本重载过）才重新注入 `planetInfo` / `noise`，并重置 `callFailed` 标志，让上一次出错的脚本有机会复活。`loadedToken()`（TerrainScript.java:171）直接返回当前 `Globals` 实例作令牌。

### 7.3 上层：`TerrainSystem.refreshParams()` 的全量失效

每帧 `update()` 先调 `refreshParams()`（TerrainSystem.java:270），其中（TerrainSystem.java:186-193）：

```java
Object ct = cfgScript.globals();          // terrainRender 配置脚本的 Globals 令牌
Object ht = TerrainScript.loadedToken();  // surfaceHeight 脚本的 Globals 令牌
if (ct != cfgToken || ht != heightToken) {
    cfgToken = ct;
    heightToken = ht;
    hCache.clear();
    clearChunks();
}
```

**为什么两个令牌都要查**（TerrainSystem.java:181-185 的 round 18 注释）：只改 `terrainRender` 参数值会被下方的参数 diff 捕获；但玩家**只改 `surfaceHeight` 函数或 `specialTerrains` 表**时，`terrainRender` 里任何值都没变，旧的高度缓存会让旧碰撞形状残留——玩家会看到一条"看不见的遗迹边界"。所以任何一个脚本重载，都**清高度缓存 + 清全部 chunk**，让一切从 lua 重新推导。

参数 diff 路径（TerrainSystem.java:194-258）：从 `terrainRender` 表读 13 个参数，逐个 clamp 到安全范围（如 `blockW ∈ [0.5, 64]`、`rangeM ∈ [2000, 500000]`、`physRangeM ≤ rangeM`，TerrainSystem.java:222-230），任何值变化则同样清缓存、必要时 `setupPlanet()` 重建列划分、清 chunk；贴图变化时单独释放/重建 `Texture`。

> 注意 `LuaScript` 非线程安全，只能从渲染线程访问（LuaScript.java:17）——`TerrainSystem` 的全部路径都在渲染线程的 `update/render` 里，符合约束。
