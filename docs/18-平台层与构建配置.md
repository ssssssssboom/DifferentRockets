# 18 · 平台层与构建配置

> 本篇覆盖 DifferentRockets 的两个平台入口（Android / Desktop）、`game/` 下全部 Gradle 构建脚本、`AndroidManifest.xml`，以及与平台层强相关的存储权限策略与 APK 签名现状。
> 所有引用均为仓库内相对路径，格式 `文件:行号`。

## 1. 模块与仓库总览

`game/settings.gradle:1-2` 定义了三个模块：

```groovy
rootProject.name = 'DifferentRockets'
include 'core', 'desktop', 'android'
```

| 模块 | 角色 | 构建插件 |
|---|---|---|
| `core` | 全部游戏逻辑（`com.differentrockets.{game,ui,util}`）+ `assets/` 资源 | `java-library` |
| `android` | 安卓 APK 打包 + `AndroidLauncher` | `com.android.application` |
| `desktop` | 桌面调试入口 `DesktopLauncher`（LWJGL3） | `application` |

根构建脚本 `game/build.gradle:1-20` 只做两件事：

- `buildscript` 引入 **Android Gradle Plugin（AGP）8.5.2**（`game/build.gradle:9`）；
- `buildscript` 与 `allprojects` 的仓库列表均把**阿里云镜像放在最前**（`maven.aliyun.com/repository/public` 和 `/google`），其后才是 `mavenCentral()` / `google()`（`game/build.gradle:2-7, 14-19`）——国内网络环境下这是构建速度的关键，接手后不要随意调整顺序。

`game/gradle.properties:1-5` 开启 AndroidX、关闭 R8 full mode（`android.enableR8.fullMode=false`），JVM 堆 3g。

**注意**：仓库中没有提交 Gradle Wrapper（`game/` 下无 `gradlew` / `gradle/wrapper/`），构建缓存目录显示本机使用的是 **Gradle 8.9**（`game/.gradle/8.9/`）。AGP 8.5.2 要求 Gradle ≥ 8.7，接手时请自备 Gradle 8.9 或用 Android Studio 同步。`game/local.properties` 指向本机 SDK：`sdk.dir=D:\\DifferentRockets\\android-sdk`，此文件是机器相关的，不要提交他人路径。

## 2. 桌面入口 DesktopLauncher

`game/desktop/src/com/differentrockets/desktop/DesktopLauncher.java` 全文仅 15 行：

```java
Lwjgl3ApplicationConfiguration cfg = new Lwjgl3ApplicationConfiguration();
cfg.setTitle("DifferentRockets");
cfg.setWindowedMode(1080, 1920); // ~phone aspect so UI proportions match
cfg.setForegroundFPS(60);
new Lwjgl3Application(new DRGame(), cfg);
```

（`DesktopLauncher.java:9-13`）

要点：

- **1080×1920 竖屏窗口**：游戏是手机竖屏 UI，`AndroidManifest.xml:19` 也强制 `portrait`。桌面窗口用 1080 宽 × 1920 高是为了**复刻手机宽高比（9:16），让 UI 比例、字号、布局在桌面调试时与真机一致**（行内注释原话：*~phone aspect so UI proportions match*，`DesktopLauncher.java:11`）。不要随手改成横屏分辨率，否则调出来的 UI 在手机上会走样。
- **前台 60 FPS**：`cfg.setForegroundFPS(60)`（`DesktopLauncher.java:12`）。
- **运行工作目录**：`game/desktop/build.gradle:21-23` 把 `run` 任务的 `workingDir` 设为 `core/assets` 的绝对路径，这样桌面端 `Gdx.files.internal(...)` 与安卓端从 APK assets 读取的行为一致。

## 3. 安卓入口 AndroidLauncher

`game/android/src/com/differentrockets/android/AndroidLauncher.java`（共 168 行）继承 `AndroidApplication`，职责分两块：libGDX 配置 + 存储权限引导。

### 3.1 onCreate：libGDX 配置

```java
AndroidApplicationConfiguration cfg = new AndroidApplicationConfiguration();
cfg.useAccelerometer = false;
cfg.useCompass = false;
cfg.useWakelock = true;
```

（`AndroidLauncher.java:22-25`）

加速度计与罗盘关闭（游戏用不到，省电），`useWakelock = true` 保证飞行/模拟过程中屏幕不熄灭。随后立刻探测存储并在需要时申请权限（`AndroidLauncher.java:26-29`，详见第 5 节），最后 `initialize(new DRGame(), cfg)`（`AndroidLauncher.java:30-31`）。

### 3.2 onResume：权限授予后的无重启热切换

这是入口里最关键的一段逻辑（`AndroidLauncher.java:35-56`）：

1. 每次 resume 都重新 `probeStorage(...)` 探测共享存储根目录是否可写；
2. 如果仍不可写且用户本会话没有明确拒绝过，再次走申请流程（`AndroidLauncher.java:43-45`）；
3. 调用 `Res.refresh()`（`AndroidLauncher.java:46`）——core 侧的 `Res.refresh()` 在资源根从「内置 assets / 应用私有目录」切换到「共享目录 `/storage/emulated/0/DifferentRocket/`」时返回 `true`（`game/core/src/com/differentrockets/util/Res.java:170-180`）；
4. 一旦切换成功，关闭权限对话框并调用 `game.reloadResources()`（`AndroidLauncher.java:47-51`），后者在 core 侧保存世界、重载零件表、重置 Mod/火焰/地形脚本等（`game/core/src/com/differentrockets/game/DRGame.java:58-64`）。

也就是说：**玩家在系统设置页授予"所有文件访问"后切回游戏即生效，不需要重启 App**。整个 `onResume` 包在 `try/catch (Throwable)` 里，失败只打 warning 不崩（`AndroidLauncher.java:53-55`）。

### 3.3 探测与日志

- `probeStorage(...)`（`AndroidLauncher.java:82-105`）：不是查权限标志位，而是**真的在 `Environment.getExternalStorageDirectory()/DifferentRocket/` 下创建 `.probe` 文件写 1 字节再删掉**，以实测结果判定共享根是否可写——比权限 API 更可靠（能覆盖"权限给了但目录仍不可写"的ROM 魔改情况）。
- `logStorageState(...)`（`AndroidLauncher.java:59-76`）：把 SDK 版本、外部存储根、`isExternalStorageManager()`、`WRITE_EXTERNAL_STORAGE` 授予状态全部打进 logcat（tag `DifferentRockets`），排查玩家权限问题时直接 `adb logcat -s DifferentRockets` 即可。注意日志里 `targetSdk=29` 是硬编码字符串（`AndroidLauncher.java:72`），改 targetSdk 时要同步改这里。

## 5. 存储权限申请策略（重点）

### 5.1 为什么需要"所有文件访问"

游戏的核心卖点之一是**玩家可直接修改资源**：首运行把 lua 脚本、贴图、XML 拷贝到共享目录 `/storage/emulated/0/DifferentRocket/`（`Res.java:9-21`），玩家用文件管理器就能改零件行为和贴图。这个目录是**共享存储根目录下的自建目录**，不属于应用私有空间，也不属于媒体集合，因此 Scoped Storage 的常规豁免（SAF、MediaStore）都不适用，只有两条路：传统外部存储模型，或 `MANAGE_EXTERNAL_STORAGE`。

### 5.2 targetSdk 29 的刻意选择

`game/android/build.gradle:10-13` 的注释把策略写得很清楚：

```groovy
// targetSdk 29: scoped-storage enforcement stays OFF on Android 11
// (requestLegacyExternalStorage honored), and plain WRITE_EXTERNAL_STORAGE
// suffices on Android <= 10. MANAGE_EXTERNAL_STORAGE covers Android 12+.
targetSdk 29
```

分级效果：

| 系统版本 | 生效机制 | 代码路径 |
|---|---|---|
| Android ≤ 9（API < 23，minSdk 24 故实际为 7.0–9） | 安装时授予清单里的 `WRITE_EXTERNAL_STORAGE` 即可 | 清单静态权限 |
| Android 10（API 29） | `requestLegacyExternalStorage` + 运行时 `WRITE_EXTERNAL_STORAGE` | `AndroidLauncher.java:119-126` 运行时申请 |
| Android 11（API 30） | targetSdk 29 时 legacy 标志仍被尊重；同时代码走 all-files 申请兜底 | `AndroidLauncher.java:115-118` |
| Android 12+（API 31+） | legacy 标志被忽略，**必须** `MANAGE_EXTERNAL_STORAGE`（"所有文件访问"设置页） | `AndroidLauncher.java:115-118, 133-167` |

运行时申请分两支（`AndroidLauncher.java:113-131`）：

- **API 23–29**：`requestPermissions(READ/WRITE_EXTERNAL_STORAGE)`（`AndroidLauncher.java:119-126`）；
- **API 30+**：检查 `Environment.isExternalStorageManager()`，未授权则弹出一个**不可取消的中文 AlertDialog** 解释原因，点"去授权"跳转 `Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` 设置页（`AndroidLauncher.java:136-147`）。对话框文案明确告诉玩家目录位置和用途，且提供"暂不（使用内置资源）"选项——选了之后置 `userDeclinedThisSession = true`，本次会话不再打扰（`AndroidLauncher.java:157-160`）。

### 5.3 权限未授予时的降级链

core 侧 `Res` 实现了双根降级（`Res.java:113-139, 187-199`）：

1. 首选共享根 `/storage/emulated/0/DifferentRocket/`（注意：通过反射调 `Environment.getExternalStorageDirectory()`，而**不是** `Gdx.files.getExternalStoragePath()`——后者自 libGDX 1.9.10 起返回的是应用私有目录 `Android/data/<pkg>/files/`，见 `Res.java:9-16, 141-161`）；
2. 不可写则退回应用私有外部目录 `Android/data/com.differentrockets/files/DifferentRocket/`（`Res.java:34, 123-127, 193-199`），游戏可正常运行，但玩家无法从文件管理器直接改资源；
3. 每次 resume 重试共享根，首次切换成功时把私有目录中**玩家未修改**的文件迁移过去（`Res.java:13-16` 注释）；
4. 两个目录都不可写时，全部资源读取回落到 APK 内置 assets（`Res.java:27-28`）。

**合规提示**：`MANAGE_EXTERNAL_STORAGE` 在 Google Play 属于受限权限，上架需要声明理由；本项目目前的分发方式决定了可以接受这一点。若未来上架 Play 商店被拒，这是第一个要回头看的点。

## 7. android 模块构建（game/android/build.gradle）

### 7.1 基本配置

- `namespace` / `applicationId` 均为 `com.differentrockets`（行 4, 8）；
- `compileSdk 34`、`minSdk 24`（Android 7.0）、`targetSdk 29`（行 5, 9, 13，targetSdk 的取舍见第 5.2 节）；
- `versionCode 1` / `versionName '1.0'`（行 14-15）；
- Java 17 编译选项（行 28-31）；
- `debug` 与 `release` 两个 buildType 均 `minifyEnabled false`（行 18-26）——**没有代码混淆/压缩**，luaj 反射调用 Box2D/Java API 的场景下这规避了大量 keep 规则问题。

### 7.2 assets.srcDirs：单一资源树共享

```groovy
sourceSets {
    main {
        java.srcDirs = ['src']
        assets.srcDirs = ['../core/assets']
        res.srcDirs = ['res']
        manifest.srcFile 'AndroidManifest.xml'
        jniLibs.srcDir 'libs'
    }
}
```

（`game/android/build.gradle:33-41`）

**`assets.srcDirs = ['../core/assets']` 是 core 与 android 共享资源的机制**：APK 的 assets 直接指向 core 模块的资源树，33 个内置 lua（`core/assets/mods/`）、贴图、XML 只有一份副本，改一处两端生效。桌面端则通过 `run.workingDir = core/assets`（`desktop/build.gradle:22`）+ core 的 `resources.srcDirs`（`core/build.gradle:16`）读到同一目录。安卓自身的 `res/` 只放启动图标等（`AndroidManifest.xml:10` 引用 `@mipmap/ic_launcher`）。

### 7.3 packagingOptions：排除玩家目录与 META-INF 冲突

```groovy
packagingOptions {
    resources.excludes.addAll(['META-INF/DEPENDENCIES', 'META-INF/LICENSE', 'META-INF/NOTICE'])
    // the desktop player-resource copy dir must never ship inside the APK
    resources.excludes.addAll(['DifferentRocket/**', 'assets/DifferentRocket/**'])
}
```

（`game/android/build.gradle:43-47`）

两类排除：

1. **`META-INF/*`**：luaj 等 jar 携带的签名/许可文件在多 jar 合并进 APK 时会冲突，直接排除；
2. **`DifferentRocket/**` 与 `assets/DifferentRocket/**`**：桌面端运行时，玩家资源拷贝目录生成在**工作目录的上一级**（`Res.java:132-136`：`Gdx.files.local("../DifferentRocket/")`），即 `game/core/DifferentRocket/`——它紧邻 `core/assets`。这条排除是防御性的：一旦玩家目录（或某人手动放的副本）出现在 assets 树内，APK 打包时会把它剔掉，**玩家修改过的 lua/贴图绝不能被打进安装包**，否则首运行拷贝逻辑会把旧内容当成出厂默认。注释原文即"the desktop player-resource copy dir must never ship inside the APK"（行 45）。

### 7.4 ABI 与原生库：copyAndroidNatives

libGDX 的原生库（`libgdx.so`、`libgdx-box2d.so`）以 `natives-<abi>.jar` 形式发布，而 AGP 只扫描 `jniLibs.srcDir` 里的 `.so`，不会解 jar。因此构建脚本定义了一个自定义任务：

- 声明独立 `natives` configuration（`android/build.gradle:50`）；
- 对 **armeabi-v7a / arm64-v8a / x86 / x86_64 四个 ABI** 各引入 `gdx-platform:1.12.1:natives-<abi>` 和 `gdx-box2d-platform:1.12.1:natives-<abi>`（行 78-81）；
- `copyAndroidNatives` 任务在 `preBuild` 前执行，按 jar 文件名识别 ABI，把 `.so` 解压到 `android/libs/<abi>/`（行 54-73），随后由 `jniLibs.srcDir 'libs'`（行 39）正常打包。

当前 `game/android/libs/` 下已有四个 ABI 目录，各含 `libgdx.so` 与 `libgdx-box2d.so`——**这是构建产物，不是手工放置的**，删掉后重新构建会再生成。四个 ABI 全覆盖意味着 APK 体积里包含 4 份原生库；若日后要瘦身，可考虑拆 ABI 分包（目前未配置 `splits` / App Bundle）。

### 7.5 安卓端依赖清单

（`android/build.gradle:75-82`）`project(':core')` + `gdx-backend-android:1.12.1` + 上述 8 个 natives jar。**没有引入 `luaj-jse` 的安卓特化版本**——luaj 是纯 Java，通过 core 的 `api` 依赖传递进 APK。

## 9. APK 签名现状

**仓库中没有任何 `signingConfigs` 配置**。`game/android/build.gradle` 的 `buildTypes`（行 18-26）只设置了 `minifyEnabled` / `debuggable`，未引用签名配置；全部 Gradle 源码中也搜不到 `signingConfig`。因此：

- **debug 构建**：AGP 自动用本机 debug keystore（`~/.android/debug.keystore`）签名，可直接安装调试；
- **release 构建**：产出的是**未签名 APK**，安装前必须手动 `apksigner sign`（或 `jarsigner` + `zipalign`），发布用的 keystore 不在仓库内——向原开发者索取或自行生成，生成后务必离线妥善保管（丢失即无法覆盖更新）；
- `versionCode` 目前恒为 1、`versionName` 恒为 `'1.0'`（`android/build.gradle:14-15`），尚无版本递增约定。

若要补签名，标准做法是在 `android` 块内加 `signingConfigs { release { ... } }` 并在 `release` buildType 引用，密码通过环境变量或不入库的 properties 文件注入。
