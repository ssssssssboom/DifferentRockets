## 0. 四个文件的职责一览

| 文件 | 职责 |
|---|---|
| `OrbitPredictor.java` | 数值传播器：Map 视图轨道预测线（`compute`）与 >4x 加速的预计算轨道跟随（`computeWarp`）共用同一套 velocity-Verlet + ΣGM/r² 引力 + 自适应步长 |
| `Planet.java` | 天体数据模型：半径/引力/大气/地形/轨道根数，Kepler 轨道推进（`updateRails`），地形高度查询（`heightAt`） |
| `PlanetDefs.java` | 从玩家可改的 lua（`mod/planets.lua` + `mod/planets/*.lua`）加载天体定义，失败时回退 `SmolarSystem.xml` |
| `SteeringIO.java` | 转向输入的共享状态（纯数据类）：UI 写、GameWorld 与 lua 控制率读 |

一个重要的事实先说明：**代码中没有显式的 SOI（sphere of influence）字段或计算**。引力永远是所有天体的 ΣGM/r² 叠加（`OrbitPredictor.java:275-289` 与 `GameWorld.gravityAt` 同一定律），"当前属于哪个天体"一律用**按表面距离最近**的规则判定（`OrbitPredictor.java:255-265`，注释声明与 `GameWorld.currentPlanet` 同一规则）。SOI 一词只出现在注释里（`OrbitPredictor.java:11,33`），指代"最近天体发生切换"这件事。

## 1. OrbitPredictor：velocity-Verlet 轨道传播器

### 1.1 输出缓冲与公共字段

传播结果直接写进公开数组，调用方（Map 绘制 / warp 跟随）零拷贝读取（`OrbitPredictor.java:23-60`）：

| 字段 | 含义 |
|---|---|
| `xs/ys` | 惯性系下的逐点位置，最多 `MAX_STEPS + 1` 个点，`MAX_STEPS = 4200`（`OrbitPredictor.java:23`） |
| `fx/fy` | **每个点上锚天体（anchor）在该点时刻的位置**——单锚帧体系的核心，见 1.3 |
| `sfx/sfy` | 每个点上太阳的位置，供 Map 切换到日心固定帧绘制（round 16，`OrbitPredictor.java:40-46`） |
| `ts` | 每个点的绝对宇宙时间（`world.time` + 累计 dt） |
| `frame` | 每个点的"信息性最近天体"，**不再用于绘制**（`OrbitPredictor.java:49-50`） |
| `anchor` | 唯一的绘制锚：`GameWorld.planets` 下标，-1 表示无（`OrbitPredictor.java:51-52`） |
| `sun` | 太阳（无 parent 的天体）在 `planets` 中的下标 |
| `offx/offy` | round 15 起废弃，仅为保持二进制形状保留（`OrbitPredictor.java:55-57`） |
| `count` / `simSeconds` / `impacted` | 有效点数 / 总传播时长 / 是否撞地终止 |

### 1.2 积分器与自适应步长

积分器是标准 **velocity-Verlet kick-drift-kick**（`OrbitPredictor.java:118-127`）：

1. 用当前加速度 `ax/ay` 做半步 drift 得到新位置 `nx/ny`；
2. 时间推进 `t += dt`，先把所有行星沿 Kepler 轨道推到新时刻（`systemAt`），再在新位置求加速度（`accelAt`）；
3. 用新旧加速度的平均值做 kick 更新速度。

也就是说**行星在传播过程中是动的**，SOI 穿越和长巡航段的父系参考帧不会因为"行星钉死不动"而失真（类注释 `OrbitPredictor.java:8-12`）。

自适应步长取最近天体的局部动力学时间 `tau = sqrt(r³/mu)` 的 0.004 倍，约 250 点/圈（`OrbitPredictor.java:240-252`）：

```java
double tau = Math.sqrt(br * br * br / pmu[bi]);
double dt = 0.004 * tau;
if (dt < 0.05) dt = 0.05;
if (dt > 20000) dt = 20000;
```

> ⚠️ **注释与代码不一致**：类 javadoc 写步长夹在 `[0.5 s, 40000 s]`（`OrbitPredictor.java:15-16`），但实际代码夹的是 **[0.05 s, 20000 s]**（`OrbitPredictor.java:249-250`）。改步长策略时以代码为准，顺手修注释。类注释还说近 Smearth 地面时 dt ≈ 1 s（`OrbitPredictor.java:246-247`），低空弧线与短时弹道都能画出足够密的点。

引力求和 `accelAt`（`OrbitPredictor.java:275-289`）对所有 `mu > 0` 的天体叠加 `mu/r²` 方向加速度，并有与 `GameWorld.gravityAt` 一致的**奇点钳制**：`r < 0.5·radius` 时按 `0.5·radius` 计（`OrbitPredictor.java:282-283`）。

### 1.3 锚帧体系 fx/fy 与"单锚帧防折叠"设计原因

Map 绘制点的公式是（`SandboxScreen.java:966-968`）：

```
drawX = xs[i] - fx[i] + anchor当前位置.x
drawY = ys[i] - fy[i] + anchor当前位置.y
```

即：把惯性系下的原始轨迹**整体平移进锚天体的当前参考帧**。关键设计（round 15，注释见 `OrbitPredictor.java:27-37`）：

- **fx/fy 永远只记录一个天体的位置**——传播开始时选定的 anchor，在整段传播中不换；
- 旧方案是"每个点各自锚定当点最近天体"，在每次 SOI 切换处会在两侧减去不同的帧速度，产生**最大约 110° 的假拐点**（20000 s 大步长下），且最近天体在采样间来回切换时轨迹会锯齿抖动；
- 单锚帧让预测线**按构造就是连续的**：换锚只需重新传播，不需要任何拼接逻辑。

anchor 的选择（round 17，`OrbitPredictor.java:85-110`）：调用方传入的 `anchorIdx` 有效（下标合法且 `mu > 0`）就用它；否则回退到传播起点的最近天体（round 15 的自动行为）。UI 侧每 `ORBIT_INTERVAL = 1/15 s` 重算一次（`SandboxScreen.java:100,1512-1514`），切换锚点时强制立即重算（`OrbitPredictor.java:80-84` 注释）。

### 1.4 compute 与 computeWarp 的分工

两个方法共享同一套 `bindPlanets` / `systemAt` / `accelAt` / `adaptiveDt`，引力模型与步长规则逐字相同——**"飞出来的轨迹"和"Map 上画的线"不可能发散**（`OrbitPredictor.java:171-178` 注释）。分工只在输出与终止条件：

| | `compute(world, ship, anchorIdx)` | `computeWarp(world, ship, dtScale, wx, wy, wvx, wvy, wt)` |
|---|---|---|
| 用途 | Map 视图预测线 | >4x 加速的预计算轨道跟随（round 19 super-warp） |
| 输出 | 内部 `xs/ys/fx/fy/ts`，上限 `MAX_STEPS=4200` 点 | 调用方数组（位置**+速度**+时间），容量 `cap = wx.length`；GameWorld 传入 `WT_MAX = 40000` 的数组（`GameWorld.java:99-104`），5 数组约 1.6 MB |
| 锚帧 | 记录 `fx/fy/sfx/sfy/frame` | 不记录（warp 跟随不需要绘制帧） |
| 步长 | `adaptiveDt(x, y)` | `adaptiveDt(x, y) * dtScale`，高倍巡航允许放大（`OrbitPredictor.java:204`）；但 GameWorld 实际**恒传 1.0**——飞与画用同一步长规则才能把轨迹粘在预测线上，4x 拉伸实测多出 5.4e-4 rad/圈相位误差（`GameWorld.java:628-634`） |
| 撞地判定 | **基准圆**：`r < radius` 即算撞（`OrbitPredictor.java:136-141`） | **真实地形**：先 `r < radius + max(0, maxHeight)` 粗筛，再用 `radius + heightAt(atan2(dy,dx))` 精判（`OrbitPredictor.java:220-231`），保证交还物理的点落在地面上而不是山里；两条线只在最后进近的米级上不同 |
| 逃逸终止 | `r_sun > 2e12 m`（`x²+y² > 4e24`，`OrbitPredictor.java:143`） | 同左（`OrbitPredictor.java:234`） |
| 返回值 | void，结果在公共字段 | 点数（int），`impacted` 标记撞地结束 |

`computeWarp` 的消费者是 `GameWorld.superWarp`（`GameWorld.java:594-641`）：进入 >4x 加速档时一次性传播，此后每帧船的状态是轨迹上**时间的纯函数**（采样间三次 Hermite 插值，速度取 Hermite 精确导数），热路径零积分、零累积漂移；在入轨/换挡/分级（零件数变化）/剩余轨迹 <20% 时低频重算（`GameWorld.java:626-636`）。撞地点会把控制权以撞击速度交还给物理（warp 回 1x）。停在地面时轨迹无意义，沿用旧的"参考帧骑行星"逻辑（`GameWorld.java:598-624`）。

### 1.5 传播循环内的行星 Kepler 推进：systemAt

`systemAt(planets, t)` 对每个天体求绝对时刻 `t` 的宇宙位置（`OrbitPredictor.java:292-315`）：

1. 无 parent（太阳）固定在 `(0, 0)`；
2. 平运动 `n = sqrt(mu_parent / a³)`，平近点角 `M = n·t + v0`，逆行天体取反（`prograde = false`）；
3. `M` 折叠到 `[-π, π]` 后做 12 次 Newton 迭代解开普勒方程，初值 `E = M + e·sin(M)`——与 `Planet.solveKepler` 同一算法（见 2.3）；
4. 由偏近点角 `E` 得轨道面坐标，绕近点幅角 `w` 旋转后**叠加到 parent 的已求位置上**。

`bindPlanets`（`OrbitPredictor.java:149-169`）依赖 `Planet.flatten()` 是**父在前**的序，因此求 `pidx`（parent 下标）时向前扫描必命中；无 parent 的第一个天体记为 `sun`。

## 2. Planet：天体数据模型

### 2.1 字段分组

`Planet.java:16-50`，一棵树（`parent` / `children`），字段分四组：

| 组 | 字段 | 说明 |
|---|---|---|
| 基本 | `name`, `gravity`（表面重力 m/s²）, `radius`（m）, `mapColor`, `icon`, `launchEnabled`, `description` | `launchEnabled=false` 的天体（如 Sun、彗星）不能作为发射场 |
| 轨道 | `a, e, w, v0`, `prograde` | 相对 parent 的 Kepler 根数；`v0` 是历元平近点角 |
| 地形 | `maxHeight, minHeight, noise`, `crustTexture`, `crustColor`, `waterDensity`, `ranges[]` | `ranges` 是角度区间 `[startDeg, endDeg]` → 高度区间 `[minH, maxH]` 的覆盖表（`Planet.java:36-39`），用于做海洋/山脉等特殊区域；`waterDensity=0` 表示无海洋 |
| 大气 | `atmoHeight`, `surfacePressure` | `surfacePressure` 以 Smearth 海平面为 1.0 |

派生量（`Planet.java:52-68`）：

- **`mu() = gravity · radius²`**——引力参数不从质量来，全由表面重力与半径算出；
- `hasAtmosphere()` 要求 `atmoHeight > 0 && surfacePressure > 0`；
- `scaleHeight() = atmoHeight / 7`；
- `densityAt(h)` / `pressureAt(h)` 是指数模型：`1.225 · surfacePressure · exp(-max(h,0)/scaleHeight)` kg/m³，`h > atmoHeight` 或 `h < -3·scaleHeight` 时为 0。

运行时状态 `pos/vel`（`Planet.java:49-50`）是宇宙系双精度米/米每秒，由 `updateRails` 每帧刷新。

### 2.2 heightAt 与地形系统的关系

`heightAt(angleRad)` 返回指定角度（弧度，世界系）上相对名义半径的地形高度，三级回退（`Planet.java:128-139`）：

1. **`TerrainScript.heightAboveDatum(name, angle)`**（玩家可改的 `mod/terrain.lua` 的 `surfaceHeight`，round 18 起**最先走这条路**）——保证高度、出生点、轨道地板等玩法查询与碰撞/渲染用的地形柱完全一致，specialTerrains 特殊区域也包含在内；
2. `TerrainScript.heightAt(name, angle)`——兼容没有 `surfaceHeight` 的旧版玩家脚本（不含特殊区域）；
3. `builtinHeightAt(angleRad)`——内置生成器，与 `mods/terrain.lua` 镜像。

内置生成器（`Planet.java:142-167`）：先查 `ranges` 是否命中特殊角度区间（支持跨 0° 环绕，`Planet.java:147-149`）得到 `[lo, hi]`，再用**以天体名 hash 为种子**的 4  octave 无缝 value noise（格点按整数周期回绕，`Planet.java:177-184`）在 `[lo, hi]` 内成形，`noise` 字段同时控制基频与粗糙度指数。因为种子来自 `name.hashCode()`，同一天体每次生成的地形完全一致。

`computeWarp` 的撞地精判（1.4 节）走的就是 `heightAt`，因此玩家改 `terrain.lua` 会同时影响渲染地形、物理碰撞和 warp 轨迹终点——这正是 round 18 注释强调的一致性（`Planet.java:129-133`）。

### 2.3 行星自身的 Kepler 推进：updateRails

`updateRails(t)`（`Planet.java:113-123`）递归刷新整棵树：本天体先由 `localPosVel` 求相对 parent 的位置/速度，叠加 parent 的 `pos/vel` 得宇宙系状态，再递归所有 children。太阳（无 parent）恒在 `(0,0)`、速度 0。

`localPosVel`（`Planet.java:87-107`）与 `OrbitPredictor.systemAt` 同公式，但**还算出速度**：`fac = n·a/(1 - e·cosE)`，轨道面速度 `(-fac·sinE, fac·√(1-e²)·cosE)`，逆行取反，再绕 `w` 旋转。`Planet.vel` 由此而来（"derived from rails"，`Planet.java:50`），地面停车时参考帧骑行星用的就是这个速度（`GameWorld.java:603-613`）。

`solveKepler`（`Planet.java:72-84`）有 round 14 的关键修复：**先把 M 折叠到 [-π, π]，再用 `E = M + e·sin(M)` 作 Newton 初值**。旧写法从 `E = M` 出发，在长会话/高倍加速（M 很大）或高偏心率时会发散，把轨道和预测轨迹"折叠"掉。`OrbitPredictor.systemAt` 内联了同一份折叠+迭代逻辑（`OrbitPredictor.java:300-308`），两处算法必须保持一致。

### 2.4 XML 解析（回退路径）

`loadSolarSystem(FileHandle)` 解析 `SmolarSystem.xml`（`Planet.java:190-202`）：根元素下的第一个 `Planet` 是太阳，`parsePlanet` 递归解析 `<Orbit>`、`<Terrain>`（含 `<Ranges>`）、`<Atmosphere>`、`<Children>`（`Planet.java:204-257`）。`flatten(out)` 按**父在前**展开成列表（`Planet.java:271-274`）——`OrbitPredictor.bindPlanets` 的 `pidx` 解析依赖这个顺序。

## 3. PlanetDefs：从 planets.lua 加载 16 天体

### 3.1 加载顺序与回退

`PlanetDefs.load()`（`PlanetDefs.java:50-75`）：

1. 玩家目录 `Res.modDir()`（即 `/sdcard/DifferentRocket/mod`）下的 `planets.lua`；
2. 同目录 `planets/` 子目录里的所有 `.lua`（**在 planets.lua 之后执行，同名定义覆盖**）；
3. 两者都没有 → 内置资源 `mods/planets.lua`；
4. lua 全部缺失或执行失败/没有任何 `definePlanet` 调用 → 回退 `SmolarSystem.xml`（`PlanetDefs.java:71-74`）。

`runScripts` 用 luaj `JsePlatform.standardGlobals()` 起一次性全局环境，只注入一个函数 `definePlanet`（`PlanetDefs.java:82-97`）：收集到 `Map<name, Def>` 里，**同名后定义覆盖先定义**（`order.remove` 再 `add`，保持"后者赢"且位置移到末尾）。脚本出错记 error 并整体回退 XML，不会带着半个星系启动。

### 3.2 父子链接与根

所有脚本跑完后统一链接（`PlanetDefs.java:110-130`）：

- `parent` 为空的定义是根（太阳），只允许一个；
- `parent` 指向未知名 → 记 error 跳过该天体（其余照常）；
- 没有任何根 → 整体失败回退 XML。

### 3.3 lua API 与 16 个内置天体

`definePlanet` 的表结构（文档注释 `PlanetDefs.java:26-39`，解析实现 `PlanetDefs.java:133-181`）：

```lua

  name="Smearth", parent="Sun", gravity=9.798, radius=637100,
  mapColor={103,157,255}, icon="Earth.png", launchEnabled=true,
  description="...",
  orbit={a=..., e=..., w=..., v=..., prograde=1},      -- 角度弧度；prograde 0 = 逆行
  atmosphere={height=70000, surfacePressure=1.0},
```

## 4. SteeringIO：转向环输入与控制率接口

### 4.1 数据本体（全部 8 行）

`SteeringIO.java:3-8` 是一个纯静态共享状态类，没有任何逻辑：

```java
public static volatile boolean ringActive = false;      // 转向环是否激活
public static volatile int buttonTurn = 0;              // -1 左 / 0 无 / +1 右（按住期间）
public static volatile double targetHeadingRad = 0;     // 环目标航向（弧度）
public static boolean hasTarget() { return ringActive; }
```

`volatile` 因为写方在 UI/输入线程、读方在物理与 lua 回调路径。角度约定与 Box2D body 角一致：0 = 船头朝"上"，逆时针为正（`ModApi.java:93`）。

### 4.2 写入方与读取方

**写入**（`SandboxScreen` 是唯一 UI 写入口，`GameWorld.setTargetHeading` 是程序写入口）：

- 转向按钮按住期间写 `buttonTurn`（`SandboxScreen.java:348-353`）；
- 转向环拖拽经 `setSteeringTarget` 单写路径写 `targetHeadingRad` 并置 `ringActive = true`（`SandboxScreen.java:356-359,448,465`）；松手/切屏置 `ringActive = false`（`SandboxScreen.java:733`）；
- `GameWorld.setTargetHeading(rad)` 供 lua（`ModApi.setTargetHeading`）以环语义命令航向（`GameWorld.java:866-871`，`ModApi.java:95-96`）。

**读取**分两层：

1. **GameWorld 船级命令** `updateSteering`（`GameWorld.java:889-913`）：`buttonTurn != 0` 时直接透传为 ±1 满速率命令并覆盖环；环激活时把 `targetHeadingRad` 视为权威值，算一个**简化比例回退**命令 `turnCommand = clamp(-err / 15°, -1, 1)`（误差超过 15° 即饱和），给 RCS 这类非发动机消费者用；无输入则命令 0。**符号约定：正命令产生顺时针力矩**（`GameWorld.java:886-887`），所以目标在船头逆时针侧（正误差）时命令为负（`GameWorld.java:905-908`）。
2. **lua 控制率**：`ModApi.getSteering()` 把三个字段镜像成 lua 表 `{active, buttonTurn, targetRad}`（`ModApi.java:110-116`），发动机脚本在 `onLoad` 里用 `part:readModText("control.lua")` 把共享控制率载进自己的 lua 状态（`ModApi.java:118-129` 及 `control.lua` 头注释）。

### 4.3 控制率：没有 PID

任务交接时最容易找错的地方：**现行控制率刻意不用 PID**。`mods/control.lua` 头注释明确写着"规则刻意简单，没有 PID"，并说明它取代了 round 9 的每引擎 PID 摇摆执行机构与 GameWorld 的船级 PI 转向（旧表仅保留、不再被读取；`GameWorld.java:875-888` 注释同样标注"superseded"）。现行规则（`control.lua` 的 `controlLaw(part)`，每个物理帧每台发动机调一次，返回该引擎的摇摆偏转角/度）：

| 模式 | 条件 | 行为 |
|---|---|---|
| BUTTON | `buttonTurn = ±1` | 所有可摇摆发动机统一打到该方向**最大摇摆角**，覆盖转向环 |
| RING | `ringActive = true` | 摇摆角 = 航向误差（度），按本引擎 `getEngineTurn()` 量程截断——误差大满偏、接近目标线性回中 |
| 无输入 | 环未激活且无按钮 | 回中（0） |

RING 模式的误差角用**矢量法**而不是角度相减：船头指向与目标指向各取单位向量，`err = atan2(二维叉积, 点积)`。叉积/点积都连续，船转过 ±180° 时误差平滑环绕、没有取模跳变，且与"航向 0 点朝哪"的全局约定无关（`control.lua` 头注释，round 13 修订）。注意 luaj 坑：必须用 `math.atan2(y, x)`，`math.atan` 的双参数形式会静默忽略第二参数（注释中实测记录）。

于是转向链路闭环为：

```
UI 转向环/按钮 ──写──> SteeringIO ──读──> GameWorld.updateSteering（比例回退 → RCS 等）
                                    └──> ModApi.getSteering → control.lua.controlLaw → 各发动机 gimbal
```

船级 PI/PID 已不存在；想在 lua 里自己做 PID 的玩家可以直接在发动机脚本里基于 `getSteering()` + `getShipHeading()` 实现，Java 侧不拦。

## 5. 易踩的坑（速查）

1. **自适应步长注释不可信**：javadoc 写 `[0.5, 40000]`，代码实际是 `[0.05, 20000]`（`OrbitPredictor.java:15-16` vs `:249-250`）。
2. **改 Kepler 求解要改两处**：`Planet.solveKepler`（`Planet.java:72-84`）与 `OrbitPredictor.systemAt` 内联版（`OrbitPredictor.java:300-308`）必须同步，否则 Map 预测线与实际行星位置分叉。
3. **改引力模型要改两处**：`accelAt`（`OrbitPredictor.java:275-289`）与 `GameWorld.gravityAt` 共享同一定律与 0.5·radius 钳制，warp 跟随的正确性依赖"飞 = 画"。
4. **预测线不要按 `frame[]` 逐点换帧绘制**——那正是 round 15 修掉的 110° 假拐点来源；永远用单一 `anchor` + `fx/fy`。
5. **地形一致性靠 `heightAt` 的三级回退**（`Planet.java:128-139`）：玩法的地形查询不要再直接调 `builtinHeightAt`，否则 specialTerrains 和玩家 `surfaceHeight` 会被绕过。
6. **`planets/*.lua` 覆盖 `planets.lua`**：排查玩家天体定义问题时，注意同名后定义赢（`PlanetDefs.java:86-92`）。
7. **找不到 PID 别惊讶**：控制率是 control.lua 的比例式 + 满偏按钮，Java 侧只有 15° 饱和的比例回退；steering/gimbal 旧表是历史遗留。
