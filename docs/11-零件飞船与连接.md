# 11. 零件、飞船与连接系统

> 适用范围：`game/core/src/com/differentrockets/game/` 下的 `PartType.java`、`PartList.java`、`Part.java`、`Attach.java`、`Ship.java`、`ShipDesign.java` 六个文件，共约 1500 行。
> 本文所有结论均来自上述源码及少量 UI 侧引用（`EditorScreen.java`、`SandboxScreen.java`），引用格式为 `文件名:行号`（行号基于阅读时的版本）。

## 1. 总览：三层模型

整个"火箭"由三个层次的对象构成：

| 层次 | 类 | 角色 |
| --- | --- | --- |
| 静态定义 | `PartType`（由 `PartList` 注册） | 一种零件的"图纸"：质量、尺寸、形状、连接点、发动机/燃料罐等子定义，从 `PartList.xml` 解析（PartType.java:109） |
| 建造蓝图 | `ShipDesign` / `ShipDesign.DesignPart` | 编辑器中的放置清单：零件 id + 编辑器坐标 + 90° 步进旋转 + 激活组 + 分级表，JSON 序列化（ShipDesign.java:13） |
| 运行时实例 | `Part` + `Ship` + `Ship.Link` | 每个零件是一个独立的 Box2D dynamic body，零件之间用 spring-damper `WeldJoint` 连接（Ship.java:19-24） |

关键设计：**零件之间不是刚体**，而是通过弹性阻尼 weld joint 传力（Ship.java:127-171），joint 参数可由 lua（`joints.lua` 或零件脚本的 `setJointParams`）覆盖。

## 2. PartType：零件的静态数据模型

### 2.1 顶层属性

`PartType` 从 `PartList.xml` 的 `<PartType>` 节点解析（PartType.java:109-210），字段包括：

- 标识：`id`、`name`、`sprite`（贴图）、`type`（语义类型字符串，默认 `"structural"`，特殊值有 `"pod"`、`"detacher"`、`"parachute"`、`"lander"` 等，见 PartType.java:122）
- 物理：`massTons`（`massKg()` = 吨 × 1000，PartType.java:104）、`width` / `height`（米）、`buoyancy`、`friction`（默认 0.4）、`drag`（nosecone 用负值）、`coverHeight`
- 编辑器行为：`category`、`hidden`、`sandboxOnly`、`ignoreEditorIntersections`、`disableEditorRotation`、`maxOccurrences`
- 规则：`canExplode`（默认 true）

### 2.2 可选子定义（能力组件）

一个零件可带以下子节点，Java 侧对应 `public` 字段，是否为 null 即"有没有该能力"：

| XML 节点 | Java 类 | 关键字段 | 判定方法 |
| --- | --- | --- | --- |
| `<Engine>` | `EngineDef` | `power`（推力 N = power × 1e6）、`consumption`（满油门燃料/秒）、`turnDeg`（gimbal 范围）、`throttleExponential`、`fuelType` | `isEngine()`（PartType.java:106） |
| `<Tank>` | `TankDef` | `fuel`（容量）、`dryMassTons`（干重）、`fuelType` | `isTank()`（PartType.java:107） |
| `<Rcs>` | `RcsDef` | `power`、`consumption`、`size` | — |
| `<Solar>` | `SolarDef` | `chargeRate` | — |
| `<Lander>` | `LanderDef` | `maxAngle`、`min/maxLength`、收放速度、宽度 | — |

燃料类型常量在 PartType.java:16-19：`FUEL_LIQUID=0`、`FUEL_MONO=1`、`FUEL_ELECTRIC=2`、`FUEL_SOLID=3`，这四个值贯穿燃料网络逻辑（见 §6.4）。

### 2.3 碰撞形状 ShapeDef

`<Shape>` 子节点给出一组顶点和 `sensor` 标志（PartType.java:26-29、175-182）。若零件没有定义任何 Shape，`Part.createBody` 会用 width/height 生成一个矩形盒（Part.java:101-111）。每个 Shape 建一个 `PolygonShape` fixture，顶点数最多取 8 个（Part.java:113）。

### 2.4 连接点 AttachPoint

见下一章。

### 2.5 PartList：全局注册表

`PartList.load()`（PartList.java:16-28）从资源 `PartList.xml` 解析出 `Map<String, PartType>`，之后做一个硬编码补丁：**所有 `type == "pod"` 且没有 `<Tank>` 的指挥舱会被补一个 50 单位 `FUEL_ELECTRIC` 的小电池**（PartList.java:19-27），干重取 `max(0.05, massTons - 0.05)`。

对外接口：`get(id)`、`all()`、`palette()`（编辑器零件面板，过滤 `hidden` 零件，PartList.java:35-41）。

## 3. 连接点类型系统：整边 vs 单点

### 3.1 两种连接点

`AttachPoint`（PartType.java:31-49）的核心字段：

- `x, y`：零件局部坐标（米，y 向上），即连接的**锚点**
- `edge`：边类型，`EDGE_NONE=0`（经典单点）或 `EDGE_LEFT/RIGHT/TOP/BOTTOM`（整边可接）
- `fuelLine`：该连接点是否参与燃料管路（见 §6.4）
- `breakAngle`（默认 180°）、`breakForce`（默认 `Float.MAX_VALUE` = 不可拉断）
- `group`、`flipX`、`order`（供 lua/编辑器使用的元数据）

XML 中连接点用 `location` 属性声明，`applyLocation`（PartType.java:212-226）把它翻译成坐标：

| location | 锚点位置 | edge | 含义 |
| --- | --- | --- | --- |
| `TopCenter` / `BottomCenter` | 上/下边中点 | `EDGE_NONE` | 单点 |
| `LeftCenter` / `RightCenter` | 左/右边中点 | `EDGE_NONE` | 单点 |
| `LeftSide` / `RightSide` | 左/右边中点 | `EDGE_LEFT` / `EDGE_RIGHT` | **整条边可接** |
| `Top` / `Bottom` | 上/下边中点 | `EDGE_TOP` / `EDGE_BOTTOM` | **整条边可接** |

即命名规则是：带 `Center` 后缀的是单点，不带后缀的 `LeftSide/RightSide/Top/Bottom` 是整边。整边的锚点仍在边中点，`edge` 标记只表示"对方零件可以接触在这条边的任意位置，weld 锚在实际接触点"（PartType.java:40-45 注释）。

### 3.2 Attach.java：共享几何工具

`Attach`（Attach.java:13）是编辑器吸附与 Ship 焊接共用的几何库，处理三种接触：

- **点 ↔ 点**：两点本身
- **点 ↔ 边**：点 + 点在线段上的投影（`closestOnSegment`，Attach.java:55-62）
- **边 ↔ 边**：两线段最近点对（`closestBetweenSegments`，Attach.java:71-92）；若两线段真正相交，距离为 0，锚点取四个端点的均值（Attach.java:84-88）

`localSegment`（Attach.java:43-52）把一个 AttachPoint 展开为局部空间线段端点：edge 类型展开成整条边（如 `EDGE_LEFT` → `(-hw,-hh)` 到 `(-hw,hh)`），单点退化为两个相同端点。

### 3.3 0.25 单位吸附量化

`EDGE_SNAP_STEP = 0.25f`（Attach.java:22）：零件沿 edge 型连接点滑动时，编辑器把吸附位置沿边方向量化到 **0.25 m 的整数倍**，垂直（接触）方向不动（`quantizeAlongSegment`，Attach.java:31-40）。单点接触不做量化。编辑器在 `EditorScreen.java:609-611` 调用它。

### 3.4 连接判定（Ship 焊接时）

`Ship.connectAttachPoints`（Ship.java:86-122）：对所有零件对 `(i, j)`、所有连接点对 `(ai, bi)`，用 `closestBetweenSegments` 算世界坐标最近距离，**取最近的一对连接点，距离 < 0.35 m 阈值即焊接**，weld 锚点取两段最近点的中点（Ship.java:115-118）。因为判定基于"线段最近距离"而非"点距离"，旋转过的零件即使只有边接触（边中点并不靠近）也能焊上（Ship.java:103-106 注释）。

## 4. Part：运行时零件实例

### 4.1 数据模型

`Part`（Part.java:21）持有一个 `PartType type`（静态定义）、所属 `Ship`、来源 `ShipDesign.DesignPart design`、Box2D `Body body`、以及**每实例独立的 lua 状态** `Globals lua` 和 `ModApi api`（Part.java:22-27）。

实例级可变状态：

| 字段 | 含义 |
| --- | --- |
| `fuel` | 当前燃料单位；构造时若为 tank 则装满（Part.java:81） |
| `deployed` | 降落伞/着陆腿展开状态 |
| `dragCd` / `dragArea` | lua 可覆盖的绝对阻力系数/参考面积，`NaN` = 用 type.drag 规则（Part.java:33-37） |
| `jointFreqHz` / `jointDampRatio` / `jointAngDamp` | lua `part:setJointParams{}` 设置的 per-part joint 覆盖（Part.java:39-48） |
| `dragExposure` | 气动暴露度 0..1，由 `Ship.updateDragExposure` 用 raycast 遮挡扫描计算（Part.java:50-56） |
| `group` | 激活组，0 = 无，1..8（Part.java:58-59） |
| `flameLevel` / `flameGimbalDeg` | 本帧火焰特效（lua `emitFlame` 设置，每帧清零，Part.java:179-182、198-201） |
| `gimbalDeg` | 发动机**实际** gimbal 偏转角，由 lua PID 驱动，推力用此值——gimbal 滞后是真实物理；不存档（Part.java:65-72） |
| `angleOffset` | 设计旋转（弧度）= `design.rot × 90°`（Part.java:92） |

### 4.2 物理体创建（createBody，Part.java:85-137）

- `DynamicBody` 且 **`bullet = true`**：对静态地形开启 CCD，防止高速撞击（500+ m/s 时一步 8+ m）穿隧地面（Part.java:88-91）
- 位置 = 船体局部坐标 `(ox, oy)`，角度 = 船体角 + 设计旋转
- `angularDamping` 取 per-part 覆盖或 `physics.lua` 的 `joints.angularDamping`；`linearDamping = 0`
- `body.setUserData(this)`：fixture 回调可反查 Part（如遮挡 raycast，Ship.java:443）
- fixture：`density = 1`；**摩擦下限 1.5**（`Math.max(1.5f, type.friction)`，因为 Box2D 按 `sqrt(fA*fB)` 混合摩擦，旧默认 0.4 会让船在任何斜坡上打滑，Part.java:123-128）；`restitution = 0`（落地零弹跳）；`isSensor` 按 ShapeDef

### 4.3 质量模型（updateMass，Part.java:140-153）

- 普通零件：`type.massKg()`
- tank 零件：`dryMassTons × 1000 + fuel`，即**燃料质量实时计入**，`setFuel` 会同步更新质量（Part.java:159-162）
- 质量下限 0.05 kg；转动惯量按矩形近似 `m(w²+h²)/12`

### 4.4 lua 钩子

```java
callOnLoad()   // 惰性创建 lua 状态后调 onLoad   —— Part.java:184-187
callOnUpdate(dt)                                 // Part.java:189-191
callOnStage()   // 置 stageActivatedThisFrame 标志 + 调 onStage —— Part.java:193-196
```

`stageActivatedThisFrame` 在 `Ship.updateScripts` 每帧末尾清零（Ship.java:542），供 lua 的 `onUpdate` 读取。

### 4.5 detachJoints：延迟拆连接

`Part.detachJoints()`（Part.java:169-177）**不会立即**销毁 joint，而是 `world.deferStructure(...)` 排队到回调后执行——因为 detacher 的 `onStage` 可能在调用方遍历零件列表时触发，就地拆船会破坏迭代。

### 4.6 连接点的世界坐标

- `attachWorldPositions()`（Part.java:211-224）：所有连接点锚点的世界坐标。注意直接 `body.getWorldPoint(local)`，**不要**先乘 `angleOffset`——`getWorldPoint` 已含完整变换，先转会二次旋转 90° 零件（Part.java:215-218 注释）
- `attachWorldSegment(index, outA, outB)`（Part.java:227-231）：edge 型连接点的世界线段端点

## 5. ShipDesign：建造蓝图的序列化格式

### 5.1 数据结构

`ShipDesign`（ShipDesign.java:13）是编辑器里的船：

- `parts: List<DesignPart>`，每个 `DesignPart` = `{ typeId, x, y, rot, group }`（ShipDesign.java:15-26）
  - `x, y`：编辑器坐标（米，y 向上）
  - `rot`：0..3，90° 逆时针步进
  - `group`：激活组 0..8，每个零件只能属于一个组
- `stages: List<List<Integer>>`：**stage 序号 → 该 stage 点火的零件下标列表**（下标即 `parts` 列表序号，ShipDesign.java:29-30）

### 5.2 autoStage 规则

`autoStage()`（ShipDesign.java:34-51）按固定顺序生成最多 3 个 stage：

1. stage 0：所有发动机（`engine != null`）
2. stage 1：所有 `type == "detacher"` 的分离器
3. stage 2：所有降落伞 + 着陆腿

空的类别跳过；若一个 stage 都没有则补一个空 stage。

### 5.3 JSON 格式

`toJson` / `fromJson`（ShipDesign.java:55-106）输出紧凑键名：

```json
{
  "parts": [
    { "t": "pod-1", "x": 0.0, "y": 4.5, "r": 0, "g": 1 },
    { "t": "fuselage-1", "x": 0.0, "y": 2.0, "r": 0 }
  ],
  "stages": [[2, 3], [4]]
}
```

- 键名：`t`=typeId，`x`/`y`=位置，`r`=rot，`g`=group（**group 为 0 时省略**，ShipDesign.java:65）
- `stages` 元素是零件下标数组
- 反序列化时 `t` 缺省回退 `"pod-1"`；若 JSON 里没有 stages 则自动 `autoStage()`（ShipDesign.java:104）

## 6. Ship：运行时飞船

### 6.1 结构组织

`Ship`（Ship.java:25）的核心字段：

| 字段 | 含义 |
| --- | --- |
| `parts: List<Part>` | 全部零件 |
| `links: List<Link>` | 全部连接；`Link = { Joint joint, Part a, Part b, boolean fuelEdge, float breakForce }`（Ship.java:30-35） |
| `stages` + `currentStage` | 分级表与当前进度（Ship.java:40-41） |
| `origin` / `originVel: Vec2d` | 本船局部坐标系原点在宇宙中的位置/速度（浮动原点，Ship.java:43-46） |
| `onRails` / `landed` | 远处非激活船走简化的轨道积分（Ship.java:597-641） |

`buildFromDesign`（Ship.java:64-83）的实例化顺序很关键：

1. 按 design 建 Part + body（design 坐标先按 spawnAngle 旋转）
2. 拷贝 stages
3. **先对所有零件调 `callOnLoad()`，再 `connectAttachPoints()` 焊接**——因为零件脚本在 `onLoad` 里用 `setJointParams` 设置 per-part joint 覆盖，焊接必须读到这些覆盖（Ship.java:78-81 注释）

### 6.2 weld：弹性阻尼连接与参数解析

`weld`（Ship.java:127-171）创建 `WeldJointDef`：

- 参数解析优先级：**`JointScript.resolve`（mod/joints.lua）> 内置 fallback**
- fallback 规则：两端零件的 per-part 覆盖里 **frequencyHz 更高（更刚）的一方胜出**，其 dampingRatio 一并采用；都没有覆盖则用 `physics.lua` 的 `joints` 表（Ship.java:146-158）
- `breakForce`：lua 给出的值优先，否则取两端连接点 `breakForce` 的较小者（Ship.java:143、157）
- `collideConnected = false`：相连零件之间不产生碰撞
- `Link.fuelEdge = apA.fuelLine && apB.fuelLine`：**两端连接点都标了 fuelLine，这条连接才算燃料管路**（Ship.java:168）
- 调试开关：JVM 属性 `dr.nojoints` 可整体禁用焊接（Ship.java:129）；`debugLastWeldHz/Damp/Source` 暴露最近一次解析结果（Ship.java:28、125）

### 6.3 连接断裂与船体分裂

- `checkJointBreaks(invDt)`（Ship.java:191-201）：每帧检查 joint 反作用力，`getReactionForce` 换算成 kN 后超过 `Link.breakForce` 即销毁
- `splitIfDisconnected()`（Ship.java:204-276）：joint 图 BFS 求连通分量；**含 pod 的分量是主船**（pod 加 10000 分，否则取最大分量，Ship.java:234-237），其余分量各生成一个新 `Ship`（继承 origin/originVel，零件与 link 整体迁移），新船 `currentStage` 设为一个极大值表示**分离残骸不能再分级**（Ship.java:256）；主船剩余 stage 中引用已失效零件下标的条目被丢弃并重排（Ship.java:259-275）

### 6.4 fuelline：燃料网络

燃料规则在 `drainScope`（Ship.java:322-354）集中定义，按 `fuelType` 分四类：

| fuelType | 名称 | 供应范围 |
| --- | --- | --- |
| 3 | solid | 只有消费者自己的罐（SRB 内部燃烧） |
| 2 | electric | 全船电网（电池没有 fuel line） |
| 1 | monopropellant | 全船所有 mono 罐（对齐 KSP 规则） |
| 0 | liquid | **仅通过 fuelline 网络**：与消费者直接相连（任意 link）的 tank 作为种子，沿 `fuelEdge` 的 link 做 BFS 取整个连通分量（`fuelComponent`，Ship.java:281-300）；消费者自身是 tank 时也含自己的网络。隔着没有 fuelLine 连接点的零件（pod、detacher、电池……）才能达到的 tank 是孤立的 |

`drainFuel`（Ship.java:362-383）在供应范围内**按比例均匀抽取**（各罐按余量同百分比下降）；`transferFuel`（Ship.java:386-416）在罐间按剩余空间比例转移，electric/mono 全船平衡，liquid 只在自己 fuelline 分量内平衡，solid 永不转移；`addFuel`（Ship.java:419-428）按空余容量比例灌入全船该类型罐。

### 6.5 分级 stage 机制

- `activateStage()`（Ship.java:513-529）：先**把下标解析成 Part 引用快照**（detacher 的 `onStage` 会延迟拆船、改动 `parts` 列表，快照保证每个成员都能触达），逐个 `callOnStage()`，然后 `world.processDeferredStructure()` 立即应用拆船，最后 `currentStage++`
- `partAt(designIndex)`（Ship.java:532-534）：design 下标 → 运行时 Part（顺序一致，但未知 typeId 的零件在建造时被跳过）
- `updateScripts(dt)`（Ship.java:538-543）：每帧清火焰 → 所有零件 `onUpdate` → 清 stage 标志

### 6.6 存档格式（区别于 ShipDesign）

`Ship.toJson/fromJson`（Ship.java:664-770）存的是**飞行状态**而非蓝图：每零件存 `t`（typeId）、`x/y/a`（body 位姿）、`vx/vy/va`（速度）、`fuel`、`dep`（deployed）、`grp`（group）；连接存为 `links: [{a, b}]` 零件下标对。读档时同样**先 `callOnLoad` 再按 links 重新焊接**（Ship.java:742-744），锚点用两端最近连接点的中点（`bestAnchor`，Ship.java:772-782）。

### 6.7 其他要点

- `controlPart()`（Ship.java:592-595）：控制参考零件 = 第一个 pod，否则第一个零件
- `updateDragExposure`（Ship.java:461-508）：每零件 8 条迎风 raycast 采样算气动暴露度，约 15 Hz 缓存，流向变化超过约 8° 或零件数变化时提前重算；**必须在 `boxWorld.step` 之前调用**（world 锁定期间禁止 raycast）
- `integrateRails`（Ship.java:598-641）：on-rails 船只做重力积分；贴地且低速时"停在地表"并跟随行星运动，且有地形硬下限防穿地

## 7. 激活组（activation group）机制

"点选一个零件，ACTIVATE 触发全组"的实现分三处：

1. **存储**：`Part.group`（Part.java:59），0 = 不属于任何组，1..8 共 8 组，每零件只能在一个组。蓝图中存于 `DesignPart.group`（JSON 键 `g`），飞行存档为 `grp`（Ship.java:689、737）。lua 可经 `ModApi.getGroup/setGroup` 读写，setGroup 会夹紧到 0..8（ModApi.java:24-25）
2. **编辑器分配**：`EditorScreen.toggleGroup`（EditorScreen.java:388-397）——选中若干零件后点组号：若全部已在该组则移出（置 0），否则全部加入；"Clear grp" 清除所选零件的组（EditorScreen.java:360-367）。组号会画在零件上（EditorScreen.java:1140）
3. **飞行触发**：`SandboxScreen.activateSelected`（SandboxScreen.java:741-766）——玩家点选一个零件再按 ACTIVATE 按钮：取 `selectedPart.group`，把**选中零件本身 + 同组所有零件**（`grp > 0 && p.group == grp`，SandboxScreen.java:753-755）先快照成列表，再逐个 `callOnStage()`，跳过已被同组先前成员激活所销毁/移走的零件，最后 `processDeferredStructure()` 立即应用拆船。`group == 0` 的零件只触发自己

注意区分：激活组与 stage 是两套独立系统——stage 由 `Ship.activateStage` 按下标表整级点火，激活组由玩家手动对单点零件触发，二者最终都汇聚到零件 lua 的 `onStage` 钩子（Part.java:193-196）。

## 8. 给接手者的注意事项（坑位速查）

- **改连接几何只改 `Attach.java`**：编辑器吸附与 Ship 焊接共用同一套最近点对算法，两边不会再漂移
- **不要绕过 `deferStructure` 拆 joint**：在 lua 回调/迭代中直接 `destroyJoint` 会破坏遍历（Part.java:164-168）
- **加新 fuelType 要同时改 `drainScope`、`transferFuel`、`tanksOf` 三处**（Ship.java:281-428）
- **per-part joint 覆盖在 `onLoad` 里设置才有效**：建造和读档都是"先 onLoad 后焊接"（Ship.java:78-81、742-744）；运行时后改的覆盖只影响之后新建的 joint
- **stage 下标是易碎引用**：船体分裂后下标失效，主船靠 Ship.java:259-275 的过滤重排兜底，分离残骸直接禁止再分级（Ship.java:256）
- **存档两份 schema 不要混用**：`ShipDesign`（`t/x/y/r/g`，蓝图）vs `Ship`（`t/x/y/a/vx/...`，飞行状态），键名相似但语义不同
