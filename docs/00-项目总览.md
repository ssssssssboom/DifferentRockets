# DifferentRockets 项目总览（00）

> 面向第一天接手代码的同事。本文只讲架构：游戏是什么、代码分几层、主循环怎么跑、为什么这样设计。
> 所有结论都来自源码，引用格式为 `文件名:行号`（路径省略 `game/core/src/com/differentrockets/` 前缀）。

## 1. 这是什么游戏

DifferentRockets 是一个 SimpleRockets 风格的 2D 航天模拟沙盒（见 `ui/MenuScreen.java:36` 的副标题
"A SimpleRockets-style 2D space sandbox"），基于 libGDX 1.12.1 + gdx-box2d + luaj-jse 3.0.1
构建（`game/core/build.gradle`），主平台是 Android，另有一个 desktop 调试启动器。

**玩法闭环**：菜单 → 建造 → 发射 → 飞行沙盒 → Map 星图 → （保存/继续/重置）。

1. **菜单（MenuScreen）**：三个入口——"Build New Rocket"、"Continue Sandbox"、"Reset World"
   （`ui/MenuScreen.java:38-61`）。
2. **建造（EditorScreen）**：从零件面板拖出零件、attach point 吸附、90° 旋转、分级（stage）
   编辑、activation group 分组、设计保存/加载（`ui/EditorScreen.java:39-43`）。新设计默认带
   一个 command pod（`ui/EditorScreen.java:85-88`）。
3. **发射**：编辑器里选发射行星，`GameWorld.launchShip(design, planet)` 把 ShipDesign 实例化
   到行星顶端的发射台上，然后切到 SandboxScreen（`ui/EditorScreen.java:544-545`、
   `game/GameWorld.java:278-365`）。
4. **飞行沙盒（SandboxScreen）**：真实 Box2D 物理 + lua 驱动的零件行为。油门、转向环、
   STAGE 分级点火、ACTIVATE 激活组、时间加速（1x~250000x）、点击零件选中
   （`ui/SandboxScreen.java:41-45`）。
5. **Map 星图**：同一屏幕内的 mapMode，画全太阳系、各行星 Kepler 轨道线和本船轨道预测线，
   可切换预测参考系（FRAME 按钮）（`ui/SandboxScreen.java:1505-1586`）。
6. **持久化**：世界每 5 秒自动存到 `save/world.json`（`game/GameWorld.java:566-570`），
   "Continue Sandbox" 读档恢复（`game/GameWorld.java:997-1029`）。

**可 mod 是这个项目的核心卖点**：首运行时全部贴图/XML/lua 被拷贝到玩家目录
（Android 上为 `/sdcard/DifferentRocket/`），玩家可以直接改零件行为脚本、物理定律、
地形生成器、行星定义甚至火焰渲染（见第 5.5 节）。

## 2. 代码分层

全部 Java 源码约 9900 行，分三个包 + 两个平台启动器：

| 层 | 位置 | 职责 |
|---|---|---|
| 平台启动器 | `game/android/src/.../AndroidLauncher.java`、`game/desktop/src/.../DesktopLauncher.java` | 进程入口、libGDX backend 初始化、Android 存储权限流程 |
| ui | `game/core/src/com/differentrockets/ui/` | 三个 Screen（菜单/编辑器/沙盒）+ 程序化 scene2d 皮肤（Ui） |
| game | `game/core/src/com/differentrockets/game/` | 全部模拟：GameWorld、Ship/Part、lua 桥接、地形、轨道预测、行星 |
| util | `game/core/src/com/differentrockets/util/` | 基础设施：资源根（Res）、JSON/XML、双精度向量、图集解析 |

数据资产（非 Java 但同等重要）：

- `game/core/assets/mods/`：33 个内置 lua 脚本（零件行为 + physics/terrain/joints/flame/control/planets 六个"系统级"脚本）。
- `game/core/assets/`：`PartList.xml`（零件静态定义）、`SmolarSystem.xml`（行星定义兜底）、
  三套 TexturePacker 图集（ShipSprites / PlanetSprites / Runtime）及 UI 贴图。

### 2.1 平台启动器

- **AndroidLauncher**（168 行）：除 `initialize(game, cfg)` 外几乎全是存储权限逻辑——
  targetSdk 29（`game/android/build.gradle`，注释说明是为了让 scoped-storage 不生效），
  API≤29 走 WRITE_EXTERNAL_STORAGE，API 30+ 弹中文对话框跳"所有文件访问"设置页；
  每次 onResume 重新探测，权限刚授予就调 `Res.refresh()` + `game.reloadResources()` 热切换
  资源根，无需重启（`AndroidLauncher.java:34-56`）。
- **DesktopLauncher**（15 行）：LWJGL3，1080×1920 竖屏窗口模拟手机比例，60 FPS
  （`DesktopLauncher.java:8-14`）。桌面玩家目录是项目根下的 `DifferentRocket/`
  （`util/Res.java:132-137`）。

### 2.2 ui 层

- **DRGame**（在 game 包但属于应用根）：libGDX `Game` 子类，`create()` 里依次
  `Res.init()` → 建 batch/font/皮肤 → `PartList.load()` → `ModManager.init()` → 加载三套图集 →
  `new GameWorld()` → 进菜单（`game/DRGame.java:30-51`）。它还持有全局共享的
  SpriteBatch/ShapeRenderer/图集，并提供 `reloadResources()` 整体热重载（`game/DRGame.java:58-76`）。
- **MenuScreen**：纯菜单。
- **EditorScreen**（1209 行）：建造编辑器。产出物是 `ShipDesign`（零件列表 + 分级表，
  JSON 可序列化，`game/ShipDesign.java:13-31`）。它只碰 PartList/PartType/Attach 这些
  "静态定义"类，不碰 Box2D。
- **SandboxScreen**（1821 行，全项目最大文件）：飞行视图 + Map 视图 + HUD。它持有
  OrbitPredictor（Map 预测线，`ui/SandboxScreen.java:98-101`）、双相机（飞行 cam + 星图 mapCam，
  后者用 double 中心坐标防 1e10 m 尺度下的 float 抖动，`ui/SandboxScreen.java:69-73`）、
  多点触控相机和转向环手势。
- **Ui**：用 1 张白色 8×8 贴图 + tint 程序化拼出的 scene2d skin，无 UI 美术依赖
  （`ui/Ui.java:15-16`）。

### 2.3 game 层（模拟核心）

按依赖关系分组：

- **世界**：`GameWorld`（Box2D World、行星表、船表、floating origin、时间加速、存档）、
  `Planet`（Kepler 轨道、大气、地形高度兜底）、`PlanetDefs`（lua 行星定义加载）。
- **船**：`Ship`（零件 body 集合 + weld joint 图 + 燃料网络 + 分级 + rails 积分）、
  `Part`（单个零件的 body、燃料、lua 状态句柄）、`ShipDesign`/`PartType`/`PartList`/`Attach`
  （静态定义与几何）。
- **lua 桥接**：`ModManager`（每零件实例独立 lua 状态）、`ModApi`（暴露给 lua 的 `part`
  对象）、`LuaScript`（单文件系统脚本的热重载加载器）、四个系统脚本桥
  `PhysicsScript`/`TerrainScript`/`JointScript`/`FlameScript`、`PlanetDefs`。
- **环境**：`TerrainSystem`（柱状地形：渲染 mesh + 碰撞 fixture）、`OrbitPredictor`
  （Map 预测线 + 高加速预计算轨迹，同一套积分器）、`FlameFx`（池化粒子）。
- **小件**：`SteeringIO`（UI↔模拟的转向共享状态，仅 8 行）、`Vec2d` 在 util 包。

### 2.4 util 层

- **Res**（591 行）：玩家资源根的解析、首 run 拷贝、版本化同步（详见 5.5）。**改任何
  资源加载行为前先读这个文件的类注释**（`util/Res.java:7-29`）。
- **Json**：手写极简 JSON writer/parser（避开 gdx-json 在 Android 上的坑，`util/Json.java:5-7`）。
- **AtlasPack**：TexturePacker XML 图集解析，含旋转 sprite 还原。
- **Vec2d**：double 精度二维向量——**宇宙坐标一律 double**，这是浮点精度设计的根基。
- **Xml**：补 `XmlReader.Element` 缺的 `getDoubleAttribute`。

## 3. 主循环数据流（一帧发生了什么）

入口是 `SandboxScreen.render(delta)`（`ui/SandboxScreen.java:987-1017`）。顺序：

### 3.1 输入 → 共享状态

- 转向：`</>` 按钮或键盘 slew 目标航向（约 45°/s），经 `setSteerTarget` 双写
  `world.setTargetHeading()` 和 `SteeringIO.targetHeadingRad`
  （`ui/SandboxScreen.java:356-360, 988-992`）。SteeringIO 是 UI 线程与模拟之间的
  volatile 共享状态（`game/SteeringIO.java:3-8`）。
- 油门写 `world.inputThrottle`；Space/STAGE 直接调 `active.activateStage()`
  （`game/Ship.java:513-529`）。
- 相机手势（双指平移/捏合缩放）只改相机，不进模拟。

### 3.2 `world.update(fd)` —— 模拟推进（`game/GameWorld.java:521-571`）

`fd = min(delta, 1/20)`（`ui/SandboxScreen.java:993`，掉帧时限制单帧模拟量）。

按当前 warp 分两路：

**物理加速（warp ≤ 4，`PHYS_WARP_MAX`，`game/GameWorld.java:33`）**：

1. 脚本（重）绑定：`PhysicsScript.ensureBound` / `TerrainScript.ensureBound`
   （lua 文件热重载后重新注入 planet 表）。
2. `updateRailsFlags()`：距 active 船 20 km（`RAILS_DISTANCE`，`game/GameWorld.java:22`）
   以外的船切 rails 模式（body 冻结，速度存入 originVel）。
3. 固定步长 substep：`PHYS_DT = 1/60`（`game/GameWorld.java:20`），每帧 1~8 步
   （warp × 帧时长换算）。每个 substep（`game/GameWorld.java:753-767`）：
   - 时间 + Kepler rails 推进所有行星；
   - `applyEnvironmentForces(active, h)`：对 active 船每个 Part 施加
     N 体引力（ΣGM/r²，可被子 physics.lua 覆盖）、大气阻力（含遮挡衰减）、
     浮力（`game/GameWorld.java:770-847`）。**Box2D World 本身零重力**
     （`game/GameWorld.java:117`），引力全部是手工施力；
   - `boxWorld.step(h, 8, 3)`；
   - floating origin 随 `frameVel` 平移；rails 船做简化引力积分。
4. 脚本行为（每帧一次，dt 为整帧模拟时长）：
   - `updateSteering()`：从 SteeringIO 解析出 -1..1 的 turnCommand
     （`game/GameWorld.java:889-913`）；
   - `active.updateScripts(dt)`：遍历零件调 lua `onUpdate(part, dt)`
     ——引擎推力、gimbal PID、燃料消耗、太阳能充电等全在这里发生
     （`game/Ship.java:538-543`）。
5. `processDeferredStructure()`：lua 回调里请求的结构变更（detacher 炸开连接等）
   统一在迭代安全点执行（`game/GameWorld.java:254-275`）。**这是铁律：lua 回调里
   绝不直接改零件/joint 图。**
6. 收尾：`checkJointBreaks`（反作用力超 breakForce 的 joint 断开，必要时船分裂）、
   `reanchorToActive()` + `velocityReanchor()`（floating origin 重新吸附到 active 船）、
   `updateLanded()`。

**超级加速（warp > 4，即 25x~250000x）**：见 5.4。无 Box2D、无 lua、引擎熄火，
active 船沿预计算轨迹采样，其余船走分块 rails（`game/GameWorld.java:549-562`）。

最后：`terrain.update()`（地形窗口管理）、每 5 秒自动存档。

### 3.3 lua 行为层在整个链路中的位置

lua 不是"插件"，而是**零件行为的本体**。以引擎为例，一帧内：

```
onUpdate(part, dt)                                   [engine-N.lua]
  ├─ part:getThrottle() / part:getTurnCommand()      → ModApi → world.inputThrottle/turnCommand
  ├─ part:drainFuel(fuelType, amount)                → Ship.drainFuel → 燃料管网（Ship.java:333-371）
  ├─ part:applyForceAt(fx, fy, lx, ly)               → ModApi → body.applyForce（挂到下一步 step）
  ├─ gimbal PID（pid 库由 ModManager 注入，
  │   ModManager.java:86-100）→ part:setGimbalDeg()   → Part.gimbalDeg（真实作动器滞后）
  └─ part:emitFlame(size, gimbalDeg)                 → Part.flameLevel（本帧渲染标记）
```

钩子共三个：`onLoad(part)`（建船/读档时，先于焊接——因为脚本可以设置
`setJointParams` 影响焊接参数，`game/Ship.java:78-82`）、`onUpdate(part, dt)`、
`onStage(part)`（分级点火时）。

### 3.4 渲染

`renderFlight()`（`ui/SandboxScreen.java:1040-`）：星空 → 行星大气光晕/本体圆盘 →
`terrain.render()`（chunk mesh + 水面）→ 各船 sprite（`drawShip`）→ 火焰
（`drawFlames` → `FlameScript`/`flame.lua` 决定画什么，Java 只批量出图元，
`game/FlameScript.java:15-32`）→ 选中零件高亮 → 转向环。
Map 模式：`renderMap()` 以 15 Hz 重算 `predictor.compute()`（`ui/SandboxScreen.java:99-101,
1505-1514`），画行星轨道线与本船预测线。

粒子（FlameFx）以模拟时间推进，暂停时冻结、加速时跟随 warp（`ui/SandboxScreen.java:998-1000`）。

## 4. 关键设计决策（为什么长这样）

### 4.1 零件间用 Box2D 弹性阻尼 weld joint 传力

- 每个零件是独立 dynamic body（`game/Part.java:85-137`），零件对之间若 attach point
  距离 < 0.35 m 就建 `WeldJointDef`，设 `frequencyHz`/`dampingRatio`——即弹簧阻尼连接，
  不是刚性焊接（`game/Ship.java:127-171`）。火箭因此会真实弯振。
- 默认参数 20 Hz / 1.1 / 角阻尼 0.08，注释明确 20 Hz 低于 60 Hz 物理步长的 30 Hz
  Nyquist 上限（`game/PhysicsScript.java:115-118`）。
- 参数三级覆盖：lua `part:setJointParams{}`（每零件，`game/ModApi.java:214-231`）→
  `mod/joints.lua` 的 `jointParams()`（每连接，`game/JointScript.java:44-79`）→
  physics.lua `joints` 表 / Java 默认。两条规则冲突时"更硬的一边赢"
  （`game/Ship.java:145-158`）。
- joint 有 breakForce：反作用力超限即断，断裂后 BFS 检查连通性，不连通就分裂成多艘船
  （`game/Ship.java:191-276`）。
- 其他细节：fixture 摩擦下限 1.5（着陆抓地）、restitution = 0（不弹）、body 设
  `bullet = true` 防高速穿透地形（`game/Part.java:91, 128-131`）。

### 4.2 每个零件实例一个独立 lua 状态

- `ModManager.createState(typeId)` 为**每个 Part 实例**新建一份 luaj Globals（源码按
  typeId 缓存，状态不共享），并预注入一个 PID 控制库（`game/ModManager.java:103-116`）。
  所以两个 engine-1 的 gimbal PID 各有自己的积分器。
- 脚本解析顺序：玩家目录 `<资源根>/mod/<typeId>.lua` 优先，内置 assets 兜底
  （`game/ModManager.java:46-74`）。
- lua 看到的 `part` 就是 `ModApi`：自身运动学、施力、船/行星/大气查询、输入
  （油门/转向/分级）、燃料管网、阻力与连接参数定制（`game/ModApi.java:7-12` 及全文）。
- lua 报错只记日志并禁用该钩子，Java 兜底行为接管——玩家改坏脚本不会崩游戏
  （`game/LuaScript.java:14-18`）。

### 4.3 ±100 km 渲染 / ±10 km 碰撞 / 10 Hz 窗口管理的柱状地形

- 地形是环绕行星的一圈**四边形列**：每列 `blockWidthM`（默认 4 m）弧宽，第 i 列是
  交接点高度 h[i]、h[i+1] 之间的四边形（`game/TerrainSystem.java:31-47`）。列共享
  交接点，天然无缝；同一份顶点同时生成渲染 mesh 和碰撞 fixture——"所见即所撞"。
- 高度来自 lua `surfaceHeight(planetInfo, xArcMeters)`（`mod/terrain.lua`），纯函数，
  按交接点索引缓存；NaN 时用内置噪声生成器兜底（`game/TerrainSystem.java:363-375`、
  `game/TerrainScript.java:121-137`）。
- 性能三段论（`game/TerrainSystem.java:48-56`）：窗口管理 10 Hz（`REFRESH_S`，
  `game/TerrainSystem.java:86`）只在 ±rangeM（默认 ±100 km）窗口边缘增删 chunk；
  高度缓存使 lua 每个新交接点只调一次；碰撞 fixture 只存在于 ±physicsRangeM
  （默认 ±10 km，否则 100 km 渲染范围 ≈ 2.5 万个 fixture）。
- 每 chunk 一个 **kinematic body**，每帧用速度驱动到跟随行星的目标位置——接触求解器
  能看到地面的真实表面速度，停在地面的船靠摩擦"坐"在移动的行星上，而不是被
  瞬移的静态碰撞体吞掉（`game/TerrainSystem.java:58-67, 290-309, 496-505`）。
- 坐标用 chunk 局部系：行星心附近的 float 顶点会触发 Box2D 2.3 原生断言
  （`game/TerrainSystem.java:63-64`）。

### 4.4 >4x 加速 = 预计算轨道跟随（super-warp）

- 时间梯子 `WARP_LEVELS = {1,2,4,25,100,1000,7500,50000,250000}`
  （`game/GameWorld.java:34`）。≤4x 正常步进 Box2D；>4x 走 `superWarp()`
  （`game/GameWorld.java:594-706`）。
- 核心思路：进入超级加速时用 `OrbitPredictor.computeWarp()` **一次性**算出 active 船
  未来轨迹（最多 40000 个采样点 ≈ 1.6 MB，`game/GameWorld.java:99-110`），之后每帧
  只做三次 Hermite 插值采样——位置速度都是时间的纯函数，无积分漂移。
- **与 Map 预测线共用同一个积分器**（velocity-Verlet + 同样的 ΣGM/r² + 同样的
  自适应步长规则，`game/OrbitPredictor.java:171-184`），所以"你飞的线就是 Map 画的线"，
  这是注释里强调的设计不变量。
- 触发重算的条件：warp 档位变化、分级/分离（零件数变化）、轨迹剩余 <20%
  （`game/GameWorld.java:709-716`）。轨迹终点是真实地形表面（含 heightAt），撞地就把
  warp 降回 1x 交还物理（`game/GameWorld.java:702-705`）。
- 停在地面时轨迹无意义，走"参考系骑行星"的旧逻辑（`game/GameWorld.java:598-624`）。
- 注意引力快路径 `gravityFast()`：超级加速下引力求值频率可达每帧千次级，绕过 lua
  直接用内置定律——玩家在 physics.lua 里改的引力只在物理加速档生效
  （`game/GameWorld.java:153-175`）。

### 4.5 版本化资源同步（玩家可改 + 官方可更新）

- 首 run 把内置资源拷贝到玩家根：`assets/`（贴图+XML）与 `mod/`（33 个 lua）
  （`util/Res.java:19-22`）。Android 优先 `/sdcard/DifferentRocket/`，权限未授予时退回
  app-private 目录，每次 resume 重试并在首次成功后迁移（`util/Res.java:113-215`）。
- **同步规则**（`util/Res.java:298-320`）：每个文件与 `.defaults/` 影子副本比较——
  玩家没动过的工厂文件随版本自动更新；玩家改过的永远保留；一组已知旧版工厂文件的
  SHA-1（`KNOWN_OLD`）用于迁移版本化机制存在之前的老安装。
- 还有一层 lua 版本头兜底：工厂 lua 头部带 `-- vX.Y.Z` 注释（`game/LuaScript.java:45-65`），
  玩家文件版本严格更旧时先备份为 `<name>.player-bak` 再覆盖（`util/Res.java:427-466`）。
- lua 系统脚本（physics/terrain/joints/flame）每秒 stat 一次玩家文件，改动即热重载
  （`game/LuaScript.java:74-81`）。存储权限刚授予时 `DRGame.reloadResources()` 整体重载
  图集/零件/lua/世界而不重启 App（`game/DRGame.java:53-76`）。
- **坑**：内置文件清单是硬编码的（`ASSET_FILES`/`MOD_FILES`，`util/Res.java:45-109`），
  因为 Android AssetManager.list() 在部分设备返回空。新增资源文件必须同步登记，
  `Res.checkManifest()` 会校验（`util/Res.java:531-554`）。

### 4.6 附：floating origin 与双精度宇宙

Box2D 是 float32，而太阳系尺度 1e11 m。方案：所有 body 只存"相对物理原点的局部
float 坐标"，原点本身的宇宙位置用 double（`GameWorld.origin`），参考系速度单独走
`frameVel` 通道——宇宙速度 = frameVel + originVel + bodyVel，body 速度因此永远远低于
Box2D 的 ~120 m/s 平移钳制（`game/GameWorld.java:66-73`）。每帧 `reanchorToActive()`
把原点吸附到 active 船质心、`velocityReanchor()` 把船速吸收进 frameVel
（`game/GameWorld.java:447-482`）。行星不模拟，全走 Kepler rails 解析解
（`game/Planet.java:86-123`）。发射新船时要小心保持既有船的宇宙位置不变——
`launchShip()` 里有大段 preserve/restore 代码处理这件事（`game/GameWorld.java:280-356`）。

## 5. 上手建议（第一天怎么读）

1. 先跑 desktop：`DesktopLauncher`，玩家目录在项目根 `DifferentRocket/`。
2. 按玩法闭环读 ui：MenuScreen（87 行）→ EditorScreen 的建造/发射出口 →
   SandboxScreen.render（`ui/SandboxScreen.java:987`）。
3. 读 `GameWorld.update()`（`game/GameWorld.java:521`）把第 3 节的流程对一遍；
   再读 `Ship.weld()` 和 `ModManager.createState()` 理解"零件 = body + lua"。
4. 想改玩法：先看 `assets/mods/` 的 lua——引擎、油箱、降落伞、轮子等 33 个零件的
   行为全在那里，Java 侧只提供 ModApi 原语。很多"游戏逻辑改动"其实不需要动 Java。
5. 注释里的 "round N item M" 是迭代轮次标记，通常附带踩坑史（如 lone-pod 下沉、
   drag-out 输入泄漏），改相关代码前值得读完所在文件的类注释。
