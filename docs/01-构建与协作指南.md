## 2. 环境要求

只需要自己装一样东西：

- **JDK 17**。三个模块都显式声明了 Java 17：
  - `core/build.gradle:4-5`、`android/build.gradle:29-30`、`desktop/build.gradle:4-5` 均为 `sourceCompatibility/targetCompatibility = VERSION_17`；
  - Android Gradle Plugin 为 `8.5.2`（`build.gradle:9`，指 `game/build.gradle`），AGP 8.x 本身就要求 JDK 17 运行。

不**需要**自己装的东西（都在仓库里）：

- **Android SDK 不用下载**：`android-sdk/` 已完整入库（platform android-34、build-tools 34.0.0、platform-tools、licenses 都在），与 `android/build.gradle:5` 的 `compileSdk 34` 对应。
- **Gradle 不用下载**：仓库根 `gradle/gradle-8.9/` 是完整发行版，直接调用 `gradle\gradle-8.9\bin\gradle.bat` 即可。项目**没有** gradlew / gradle-wrapper，不要去找 wrapper。
- **Maven 依赖走阿里云镜像**：`game/build.gradle:3-4` 和 `13-18` 把 `maven.aliyun.com` 放在 mavenCentral/google 之前，国内网络首次构建即可拉取 libGDX 1.12.1 与 luaj-jse 3.0.1（`core/build.gradle:11-13`）。

`game/gradle.properties:1` 给 Gradle 守护进程分配了 `-Xmx3g`，并开启 `org.gradle.caching=true`（`gradle.properties:3`）。

## 3. clone 后直接编译的三条命令

在仓库根目录的 Windows 命令行（cmd / PowerShell 均可）下：

```bat
:: (1) 一次性：告诉 AGP SDK 在哪。game/local.properties 被 git 忽略（.gitignore:16），
::     每个人 clone 后都要自己写这一行，路径按你机器上的实际 clone 位置改。
echo sdk.dir=D:\\DifferentRockets\\android-sdk > game\local.properties

:: (2) 编译 debug APK（用的是仓库自带的 Gradle 8.9）
gradle\gradle-8.9\bin\gradle.bat -p game assembleDebug

:: (3) 装机（用仓库自带 platform-tools 里的 adb）
android-sdk\platform-tools\adb.exe install -r game\android\build\outputs\apk\debug\android-debug.apk
```

说明：

- 第 (1) 步参考仓库里现有文件的格式：`game/local.properties:1` 就是一行 `sdk.dir=D:\\DifferentRockets\\android-sdk`（注意 properties 文件里反斜杠要转义成 `\\`）。如果换机器/换路径，只改这个文件。
- `assembleDebug` 会自动先跑 `copyAndroidNatives`：该任务把 `gdx-platform` / `gdx-box2d-platform` 四个 ABI（`armeabi-v7a`、`arm64-v8a`、`x86`、`x86_64`）的 `.so` 从 natives JAR 解到 `android/libs/<abi>/`，AGP 才会把它们当 JNI 库打进 APK（`android/build.gradle:50-73`）。这是手动注册的 `preBuild` 依赖，不需要单独调用。
- 模块结构：`settings.gradle:1-2` 声明 `rootProject.name = 'DifferentRockets'`，`include 'core', 'desktop', 'android'`。

## 4. APK 产出路径

- 构建输出：`game\android\build\outputs\apk\debug\android-debug.apk`
  （与 `tools/apk_asset_diff.py:3` 中硬编码的校验路径一致。）
- 构建配置要点（`android/build.gradle`）：
  - `applicationId 'com.differentrockets'`、`minSdk 24`、`compileSdk 34`（`android/build.gradle:5-9`）；
  - **`targetSdk 29` 是刻意为之**（`android/build.gradle:10-13` 的注释）：保持 Android 11 上 scoped-storage 不强制生效（`requestLegacyExternalStorage` 仍然有效，见 `AndroidManifest.xml:14`），Android ≤10 用普通 `WRITE_EXTERNAL_STORAGE` 即可，Android 12+ 靠 `MANAGE_EXTERNAL_STORAGE`（`AndroidManifest.xml:7`）。不要轻易升 targetSdk，会打破玩家资源目录机制（见 §6）。
  - `versionCode 1` / `versionName '1.0'`（`android/build.gradle:14-15`），发版时记得手动递增；
  - debug 与 release 都 `minifyEnabled false`（`android/build.gradle:19-26`），没有配置 release 签名；
  - `packagingOptions` 明确排除了 `DifferentRocket/**`，保证桌面版玩家资源目录**不会**被打进 APK（`android/build.gradle:43-47`）。
- 仓库根的 `DifferentRockets.apk` 只是某次构建的归档拷贝，不是构建产物路径。

## 5. 桌面版运行方式

调试物理/ UI / Lua 时优先用桌面版，改完代码秒级重跑：

```bat
gradle\gradle-8.9\bin\gradle.bat -p game desktop:run
```

- 入口：`desktop/build.gradle:11` 指定 `mainClass = 'com.differentrockets.desktop.DesktopLauncher'`。
- 窗口：1080×1920 竖屏、前台 60 FPS（`DesktopLauncher.java:11-12`），刻意模拟手机比例，保证 UI 排版一致。
- **工作目录是 `game/core/assets`**（`desktop/build.gradle:22` 的 `run { workingDir = ... }`）。这带来两个后果：
  1. libGDX 的 `Gdx.files.internal` 直接指向 `core/assets`，改贴图/Lua 后重新运行即生效；
  2. 桌面版的玩家资源目录落在 `core/assets` 的**父目录**，即 `game/core/DifferentRocket/`（`Res.java:132-137` 用 `Gdx.files.local("../DifferentRocket/")`），这样玩家拷贝永远不会混进 Android 的 assets 树被打进 APK（注释见 `Res.java:17-18`）。
- 依赖 LWJGL3 后端（`desktop/build.gradle:16-18`）。

## 6. `/sdcard/DifferentRocket` 玩家资源目录机制

这是本项目和普通 libGDX 游戏最大的区别，改资源相关代码前务必读懂 `game/core/src/com/differentrockets/util/Res.java`（591 行）与 `AndroidLauncher.java`。

### 6.1 目录长什么样

首次运行会把内置资源拷贝到玩家可访问的目录（`Res.java:19-21` 的类注释）：

```
/sdcard/DifferentRocket/            ← Android 共享存储根（即 /storage/emulated/0/DifferentRocket/）
├── assets/    贴图 + XML 配置（玩家可改）
│   └── .defaults/   上一轮出厂字节的影子副本（自动更新判定用，勿手改）
├── mod/       33 个 Lua 零件脚本 + planets.lua（玩家可改）
│   └── .defaults/   同上
└── （运行时还会生成存档等，不在 git 内）
```

`.defaults/_README.txt` 由程序写入，中英文提示"此目录为参考副本，请勿修改"（`Res.java:415-418`）。

### 6.2 Android 上的双 root 与权限流程

- core 模块没有 android.jar，共享存储根通过**反射**调 `Environment.getExternalStorageDirectory()` 取得（`Res.java:141-161`）；刻意**不用** `Gdx.files.getExternalStoragePath()`，因为 libGDX ≥1.9.10 那个 API 返回的是应用私有目录（注释 `Res.java:9-13`）。
- 双 root：优先共享根 `/sdcard/DifferentRocket/`，不可写时回退应用私有根 `Android/data/<pkg>/files/DifferentRocket/`（`Res.java:33-34`、`187-215`）。授权成功后每次 `onResume` 都会 `Res.refresh()` 重试共享根，**无需重启 App** 即切换，并把私有目录里玩家已有的文件按"只补缺、不覆盖"原则迁移过去（`AndroidLauncher.java:35-56`、`Res.java:238-264`）。
- 权限申请按 API 分级：API ≤29 走运行时 `WRITE_EXTERNAL_STORAGE`；API 30+ 弹不可取消的中文对话框引导用户去开"所有文件访问"（`AndroidLauncher.java:113-167`）。用户可点"暂不（使用内置资源）"，此时所有资源读取回退到 APK 内置 assets（`Res.java:200-205`）。
- 可写性判断用"写探针文件再删掉"（`probeWritable`，`Res.java:217-230`），不依赖权限标志位，logcat tag 为 `storage` / `res`。

### 6.3 版本化同步：玩家改过的 lua 不会被覆盖

每次启动都会跑一次 `syncTree`（`Res.java:315-425`），对每个内置文件按字节比对决策：

| 玩家文件状态 | 动作 | 日志关键字 |
| --- | --- | --- |
| 文件缺失 | 拷贝新默认值 | `copied` |
| 与内置默认字节一致 | 不动 | `kept-current` |
| 与 `.defaults/` 影子副本一致（玩家没动过） | 用新版默认覆盖 | `auto-updated` |
| 命中 `KNOWN_OLD` 里的历史出厂 SHA-1（`Res.java:273-296`） | 用新版默认覆盖 | `auto-updated` |
| Lua 且版本头严格旧于内置版（`-- vX.Y.Z` 头，`Res.java:427-466`） | 备份为 `<name>.player-bak`（只保留第一代）后覆盖 | `auto-updated (older factory version ...)` |
| 其他（玩家改过 / 首次部署无法判定） | 保留玩家文件 | `kept-player` / `kept-unknown` |

对应地，**仓库里每个内置 lua 的第一行必须是 `-- vYYYY.MM.DD[.n]` 版本头**（如 `mods/control.lua` 第一行 `-- v2026.07.22.1`），新增/修改 lua 时用 `tools/add_version_headers.py` 补头；改了 lua 却不 bump 版本头，老玩家的自动更新判定会失效。

### 6.4 显式文件清单

内置文件**不靠目录枚举**，而是硬编码两份清单：`ASSET_FILES`（`Res.java:45-73`）和 `MOD_FILES`（`Res.java:75-109`）。原因是部分设备上 Android `AssetManager.list()` 返回空数组，曾导致玩家目录建好了却是空的（注释 `Res.java:38-44`）。

**新增贴图/XML/Lua 时必须同步把文件名加进这两份清单**，否则玩家目录里不会有该文件；桌面版 `SmokeScreen` 会调 `Res.checkManifest()`（`Res.java:531-554`）校验清单与实际 assets 是否一致，漏加会在启动日志里报 `MISSING FROM MANIFEST`。

### 6.5 桌面版对应物与 git

桌面版玩家目录是 `game/core/DifferentRocket/`（§5）。这份运行时生成的目录**当前被提交在 git 里**（含 `.defaults/`），`android/build.gradle:46` 的 `packagingOptions` 排除规则保证它不会进 APK。协作时请注意：在桌面版跑过游戏后该目录内容可能变化（`.defaults` 会随内置资源刷新），提交前用 `git status` 看一眼，避免把无意义的运行时变更带进提交。

## 7. git 协作注意

### 7.1 .gitignore 排除了什么

`.gitignore`（28 行）分四组：

1. **临时与调试**（`.gitignore:1-11`）：`tmp/`、`tmp-tools/`、根目录的 `1`、`1.png`–`4.png`、`bug*.png/jpg`——截图/草稿直接丢根目录也不会进 git。
2. **构建产物**（`.gitignore:13-16`）：`game/*/build/`、`game/build/`、`game/local.properties`——所以 **SDK 路径配置不入库，每人 clone 后自己写一行**（§3 第 (1) 步）。
3. **Gradle 缓存**（`.gitignore:18-20`）：`.gradle/`、`**/build/`；注释明确"发行版本体 `gradle/` 已入库"——缓存忽略、发行版保留。
4. **IDE**（`.gitignore:22-28`）：`.idea/`、`*.iml`、Eclipse 系文件。

### 7.2 为什么 SDK 和 Gradle 发行版要入库

仓库里 `android-sdk/` 约 11251 个文件、`gradle/gradle-8.9/` 297 个文件全部入库。目的：

- **clone 即编译**：新同事不用装 Android Studio、不用跑 SDK Manager 接受 license，三条命令出 APK（§3）；
- **工具链锁死**：所有人用同一份 platform android-34 + build-tools 34.0.0 + Gradle 8.9，杜绝"我机器上能编"问题；
- **离线可编**：除 Maven 依赖（首次）走阿里云镜像外，构建不依赖本机任何预装环境。

代价是仓库体积大，接受这一点，不要把 SDK 从 git 里清出去。

### 7.3 提交与推送节奏

从现有历史（`git log`）可看到的约定：

- 首个提交是完整游戏源码+资源；随后**大文件分批入库**——SDK/Gradle 等约 1.1 万个文件被拆成"完整资源分批入库 (1)–(7)"七个提交，避免单个巨型提交推送失败。以后如需新增大批量二进制，沿用这种分批方式。
- 目前所有提交集中在同一天（2026-07-23），仓库处于交接初始状态；没有分支策略约束，直接在主线上小步提交即可。
- 提交前自查：`game/core/DifferentRocket/`（桌面运行时目录，§6.5）和 `android/libs/`（`copyAndroidNatives` 解出的 `.so`）是否被意外改动；`.gitignore` 没有忽略 `android/libs/`，注意不要把它提交进去。

## 8. `tools/apk_asset_diff.py` 的用途

发版前的**资源一致性校验脚本**（58 行，无第三方依赖，系统 Python 直接跑）：

```bat
python tools\apk_asset_diff.py
```

它做三件事（`apk_asset_diff.py`）：

1. **逐字节比对**：遍历 `game/core/assets`（`apk_asset_diff.py:4`）下每个文件，与 APK（`apk_asset_diff.py:3` 硬编码的 `android-debug.apk`）内同名条目比 SHA-256，报告 `MISSING in apk`（磁盘有、APK 没有）和 `BYTE MISMATCH`（内容不一致），跳过桌面专用的 `bin/`（`apk_asset_diff.py:20-21`）。
2. **lua 版本头新鲜度检查**：APK 里每个 `mods/*.lua` 的第一行必须有 `-- v` 版本头且不旧于基线 `MIN_VER = (2026, 7, 21)`（`apk_asset_diff.py:36-48`）——版本头是逐文件修改戳，一轮改动只 bump 被碰过的文件，低于上一轮基线即说明 APK 里混进了陈旧拷贝（注释 `apk_asset_diff.py:33-35`）。
3. 输出统计并给出 `RESULT: PASS/FAIL`（`apk_asset_diff.py:50-58`）。

**使用时机**：改了 `game/core/assets/` 里任何贴图/XML/Lua 并重新打包后、准备把 APK 交付或归档前跑一遍，FAIL 就说明 assets 改动没进包或版本头忘了 bump（配合 `tools/add_version_headers.py` 修）。注意脚本里的两个路径是**硬编码绝对路径**，仓库换位置后要同步改 `apk_asset_diff.py:3-4`（`tools/add_version_headers.py` 同理）。

`tools/` 下其余脚本：`LuaCheck.java` 用 luaj 离线编译检查 lua 语法；`crop_throttle.py` 处理油门条贴图裁剪（产物见 `shots/crop-*.png`）。
